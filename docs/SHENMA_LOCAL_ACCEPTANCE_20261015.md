## 4. 建议验收顺序

1. 先用 `smxs` 登录业务 Web，查看工作台、客户、商机、跟进记录及任务，核对本人对应内容能读出，详情与关联跳转正常。
2. 先用已有跟进检查列表、详情与关联跳转，再按下文进行客户建档申请和个人视图的真实写入验收。本环境没有启用模型，涉及转写或智能整理的新增跟进全流程另行联调。
3. 退出后用 `smxs2` 登录，确认显示的是销售二的业务，且销售一刚录入的记录不会因为同团队而自动开放。
4. 用 `smzg` 查看北区团队，确认能按权限查看北区销售记录；选择华东人员、团队或其他筛选条件不能扩大权限。
5. 用 `smzjl` 查看主公司范围，确认可汇总北区和华东；仍不能读取第二隔离公司的客户与跟进。
6. 最后用 `smother` 登录，确认只读到第二公司的对应业务。跨公司测试不需要在地址中手动替换其他客户或人员编号。
7. 运营与系统管理员的后台能力与业务范围分别核对，以实际权限裁剪为准，不能将“能登录后台”视为可以绕过公司隔离。

## 5. S2：客户建档申请与审批

1. 用 `smxs` 在客户页进入“客户建档 · 申请与进度”，选择“填写申请”。
2. 使用新的虚构客户名称和唯一的公司客户编号 / 审批单号，填写所需团队、联系人等资料，提交后在“我的申请”核对待审批状态。
3. 提交申请不应立即创建已归属的客户。销售账号不能直接在后台审批自己的建档申请。
4. 退出并用 `smyy` 或 `smadmin` 登录后台，在“建档审批”找到该申请，检查内容后通过或驳回；驳回必须填写原因。
5. 再以 `smxs` 登录，刷新“我的申请”，核对审批结果；审批通过只完成建档，客户仍待认领，不会自动归属于申请人。
6. 如需归属本人，按原有客户认领流程另行申请和审批。建档审批与认领审批是两个步骤。
7. 可另提交一条申请，在审批前由本人撤回；撤回或驳回不应创建客户。重复名称或编号的失败应有明确提示，不能通过反复提交产生重复客户。

## 6. S3：个人商机视图

1. 用 `smxs` 进入商机列表，设置搜索词、阶段等组合筛选，再从“视图设置”调整显示字段、顺序、排序与分组。
2. 选择“保存为新视图”，填写名称。刷新页面，再次选择该视图，核对配置与结果恢复。
3. 调整配置后使用“更新当前视图”；单独测试“重命名”，确认只改名称，没有偷偷覆盖配置。
4. 用另一账号登录，确认看不到 `smxs` 的私人视图。切回 `smxs`，原视图仍可读取。
5. 删除测试视图，只应删除查看配置，不删除任何商机。可见数据仍由当前业务权限控制，保存视图不会授权其他团队或其他公司的数据。
6. 本批不开放团队共享视图。版本冲突、保存失败或失效配置应显示提示；不能将页面临时状态当作已经保存成功。

## 7. 跟进记录、日期和权限

1. 进入“跟进记录”，分别选择本人、部门或成员，以及今日、本周、本月或自定义日期；这些条件只能收窄原授权范围。
2. 依次测试时间、人员、客户、商机和表格视图。搜索后核对摘要，打开详情核对完整内容。
3. 客户、商机链接依赖原有详情权限。没有明确权限的关联内容保持不可跳转；查看跟进不意味着获得所有关联业务的编辑权限。
4. 一条记录关联多个商机时，跟进条数只算一次；客户按全部可见关联客户的稳定编号去重，跨客户商机应跳到各自客户的正确入口。
5. 切换账号后确认旧账号记录与详情已清除。人员目录出现某个候选名字不代表取得该人员业务数据的访问权限。
6. 无数据、读取失败和结果尚未完整读取应有区别。遇到错误先保留筛选并重试；记录较多时缩小日期或人员范围，不将未完成分页的结果当成完整总量。
