# 神码 1.2.1 迁移实施清单

## 1. 使用方式

这份清单把内部 1.2.1 拆成神码可以独立回滚的增量批次。2026-10-15 15:32 左右只读复核，神码线上仍为 `094841a` / `V159`，就绪检查正常；本轮无线上写入。因此内部同编号迁移不能原样复制。每一批都要在隔离数据库完成迁移、接口测试、角色验收和数据回读后，才能进入下一批。

本清单是实施顺序和验收边界，不代表下列功能已经部署到神码线上。

## 2. 批次总览

1. **S1：数据和权限保护层**
   - 目标：冻结 V159 现状，建立快照、演示数据过滤和迁移回滚检查。
   - 范围：数据库快照、配置快照、账号/角色/团队/客户/商机/跟进/周报/飞书绑定清单。
   - 依赖：无。
   - 验收：快照可读、行数和关键字段可回读；正式数据与 `data_kind=demo` 数据边界清晰。

2. **S2：客户建档申请与运营审批**
   - 目标：把“申请建档”和“客户认领”拆开，减少重复客户和归属不清。
   - 神码迁移编号：`V160`，不能使用内部 `V204` 编号；目前只在本机临时库执行。
   - 后端：新增申请、列表、审批和撤回接口；审批通过时复用神码现有客户创建事务，保留 `company_reference`、团队选择和正式数据默认标记。
   - 前端：销售、主管、销售总经理提交本人申请；运营/管理员审批；申请通过后进入待认领状态，仍需单独认领审批。运营直接建档入口保留。
   - 依赖：神码已有认领流程和客户创建校验；必须保留神码公司的角色范围。
   - 验收：销售不能直接审批；审批通过只创建一条客户；重复企业编号或名称命中时给出可追溯原因；审批失败不产生孤立客户。
   - 当前状态：实现与本地隔离验收完成。小程序源码 869、Web verify 142、业务 Web 浏览器 3、后台浏览器 5、HTTP + PostgreSQL 60、合同/权限/OpenAPI 21 项通过；SQL 13 组及升级 6 组通过，103 张既有数据表指纹不变。
   - 证据边界：浏览器交互使用合成 API 回应；真实数据库链路由 HTTP、SQL 和升级脚本单独证明。未部署 S2、未上传小程序或做真机/客户验收，详见 [S2 验收记录](S2_CUSTOMER_CREATION_ACCEPTANCE.md)。

3. **S3：商机个人视图和字段偏好**
   - 目标：支持商机列表自选字段、组合筛选、排序、分组和保存常用视图。
   - 建议神码迁移编号：`V161`，不能使用内部 `V205` 编号。
   - 后端：新增用户/团队范围的视图配置和查询接口，不改变客户、商机主数据。
   - 前端：只在当前用户权限范围内展示字段和记录；视图配置不越权扩大数据范围。
   - 依赖：先确认神码 Web 商机列表的实际来源和接口契约；小程序只复用筛选口径，不强行引入完整 PC 视图。
   - 当前门槛：已允许独立本地实现；先固定 S2 提交及契约/验收记录，再接入共享路由和权限文件。S3 单独提交、迁移和验收，不混入 S2 发布包。
   - 验收：销售只能看到本人范围，主管看到团队范围；保存、修改、删除视图均可回读；视图失效时使用安全默认查询。

4. **S4：商机金额和预测口径**
   - 目标：分离预测、实际确收和回款，补充金额确认规则。
   - 建议神码迁移编号：`V162`，不能把内部 `V187` 只当成 SQL 白名单迁移。
   - 后端：先补规则白名单和金额确认 API，再接入前端金额入口；保留神码现有阶段和权限规则。
   - 依赖：确认神码当前商机金额字段、财务来源和实际回款口径。
   - 验收：阶段概率不无提示改写预测值；实际确认保留来源、确认人和时间；历史数据读回不变。

5. **S5：CRM 只读首批接入**
   - 目标：读取客户、商机、人员和组织，按 CRM 唯一编号建立关联。
   - 建议迁移编号：`V163` 起按最终字段设计连续编号。
   - 后端：增加外部来源、同步游标、错误记录和幂等键；先做首次导入，再做新增/修改/负责人变化。
   - 依赖：集团 CRM 接口文档、字段字典、测试环境、调用权限、人员对应关系和删除/转移规则。
   - 验收：重复导入不重复建档；负责人和团队变化可回读；CRM 不可用时不影响本地正常录入；首期不写回 CRM 主数据。

6. **S6：飞书同步和周报扩展**
   - 目标：在保留神码现有 Base、群聊和周报绑定的前提下，补充失败重试和报告周期扩展。
   - 建议迁移编号：按神码 Feishu 当前写入边界另行连续编号，不直接复制内部 V188/V192/V195/V206。
   - 后端：跟进记录入表、群通知、周报记录和发布任务分别留痕，演示数据不进入正式目标。
   - 前端：沿用神码现有周报入口；日报、双周报、月报、季度报逐项开放。
   - 依赖：神码飞书应用身份、Base/表/群 ID、权限审批和周报字段方案。
   - 验收：同一业务记录不重复写入或推送；失败可重试；演示数据严格排除；周报记录可在多维表格回读。

7. **S7：小程序和 Web 体验同步**
   - 目标：移植已验证的表单、金额、产品线、异常恢复和报告交互。
   - 依赖：S2–S6 接口稳定；神码小程序 AppID、域名、蓝色视觉和后台入口不变。
   - 验收：保存回执丢失时可查回且不重复创建；草稿可恢复；角色看到的字段和数据范围一致；旧账号仍可用。

8. **S8：认证和组织入口增强（最后一批）**
   - 目标：评估手机号优先登录、公司入口和二次认证。
   - 建议：最后实施，不与业务数据迁移同批发布。
   - 原因：会影响神码 `smAdmin`、中台管理员、演示账号和现有密码登录；必须先完成账号去重和回滚演练。

## 4. 每批发布前检查

1. 记录神码代码提交、数据库迁移头、运行配置指纹和数据批次指纹。
2. 在隔离数据库执行迁移，并对账号、角色、团队、客户、商机、跟进、周报、飞书配置做前后快照比对。
3. 使用销售、主管、销售总经理、运营管理员、中台管理员和演示账号分别验证允许与拒绝路径。
4. 执行小程序和 Web 自动化测试，再做一条真实隔离链路：录入跟进 → 入飞书表 → 群通知 → 生成周报 → 周报记录回读。
5. 验收失败时只回滚当前批次，不回滚神码已有 V152–V159 定制。
