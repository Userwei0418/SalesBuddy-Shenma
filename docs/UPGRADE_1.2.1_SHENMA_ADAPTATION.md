# 神码 SalesBuddy 1.2.1 适配矩阵与升级方案

## 1. 文档目的

本文是神码版本升级到内部 1.2.1 的适配基线。升级采用“内部通用能力同步、神码定制能力保留、外部接口按神码实际情况适配”的方式，不直接覆盖神码现有代码、数据库或运行配置。

本文只记录代码和方案边界，不代表 1.2.1 已经在神码环境上线。正式版本必须以升级后的版本文件、数据库迁移回执、隔离验收回执和部署回执为准。

## 3. 内部 1.2.1 目标基线

1. 初次研究时内部后端目标为 `5fcb469` / V246；本次新 UI 核对时内部事实源已登记配套后端 `5c2dad4` / V250。Web UI 固定来源为 `e6099547ddaab0f1e4534c6216e7b9977e3c7368`，不从内部未提交工作区直接复制。

3. 内部 1.2.1 的 M3 报告、任务和团队范围能力仍有独立验收阻断。因此本适配不把这些内容自动标记为“可上线”，需要单独完成神码隔离验收后再决定是否纳入。

## 4. 必须同步的通用能力

1. 客户建档申请、审批、未认领和认领的流程历史，保留销售只能申请、运营或管理员审批的权限边界。
2. 商机列表的组合筛选、排序、分组和个人常用视图保存。神码已有的销售范围和团队范围权限继续生效。
3. 手机号或公司入口相关的登录兼容能力。原有账号密码登录不能被直接删除，老账号必须可继续使用。
4. 商机预测、实际确收和回款的分离口径。预测值不能被阶段概率无提示地改写，实际确认值必须保留来源和确认记录。
5. 商机保存异常后的结果查回和幂等保护。网络超时或回执丢失时先查询原提交结果，不能提示用户重复创建。
6. 统一的错误、加载、空状态和权限拒绝反馈，保证小程序和 Web 的业务结果一致。

## 5. 需要结合神码改造后同步的能力

1. CRM 数据接入。CRM 仍是客户和商机主数据来源；首期读取客户、商机、人员和组织信息，按 CRM 唯一编号关联。首期不直接改写 CRM 主数据，跟进回写需等 CRM 对接方确认接口和回执规则。
2. CRM 字段和业务阶段映射。必须先取得正式字段字典、状态字典、人员对应关系、删除或转移规则和增量接口，再实现导入和持续同步。
3. 飞书跟进和周报同步。保留神码当前多维表格、群通知、周报记录和现有绑定；内部通用同步代码只能作为实现参考，不能覆盖神码的 Base、群、应用身份或 Key 配置。
4. Web 工作台。已在隔离候选中接入内部 PC 2.0 框架，适配神码客户、商机、跟进记录与周报；新只读跟进接口沿用原权限。完整商机工作区、报告 V3 等后续能力见 WEB_PC_1.2.1_SHENMA_ADAPTATION.md，不直接替换现有中台或销售后台。
5. 工作报告。保留神码已有周报生成、编辑、历史和飞书发布能力；日报、双周报、月报、季度报、自定义章节、会议演示和离页恢复逐项适配，未通过真实模型和权限验收的功能不开放给正式用户。
6. 小程序 UI。继承神码现有蓝色视觉、页面布局、客户 Logo、域名和业务视角，只移植内部已验证的表单、金额、产品线和异常恢复能力，不替换神码 AppID 或请求地址。

## 6. 必须保留的神码定制能力

1. 神码独立 AppID、域名、证书、销售服务器、中台服务器、数据库和运行服务，不能与内部环境混用。
2. 神码现有小程序蓝色 UI 及 1.0.8 适配后的页面风格、销售/FDE 视角切换、团队归属和多人任务习惯。
3. 神码自己的账号、组织、角色、65 个业务账号上限和 `smAdmin` 运营/管理账号。内部账号和组织不能覆盖神码名单。
4. 神码 V152–V159 专属数据库迁移，包括账号额度、隔离演示公司、试用模拟数据、周报飞书发布和发布写入边界。
5. 演示数据后台标记。模拟客户、商机及其后续记录继续使用后台 `data_kind=demo` 和批次来源标记，前端不显示“演示”字样；正式周报、正式飞书同步和销售能力评估不得混入模拟数据。
6. 统一模型密钥的运维入口和密钥不回显规则。神码运维可更换 Token Plan Key，销售业务管理员不能在业务页面显式修改 Key；密钥不进入前端、日志、源码或交付文档。
7. 神码中台的独立 Agent、知识库、发布绑定和管理员入口。只同步接口契约和必要的 Agent 配置，不复制内部中台账号或发布密钥。

## 7. 数据库和代码迁移原则

1. 不覆盖神码 V152–V159 文件，也不把内部同编号迁移直接复制到神码。
2. 以神码 V159 为基线，为选定能力新建连续迁移，例如从 V160 起按神码实际依赖重新编号，并为每个迁移记录来源、依赖和回滚边界。
3. 先在神码数据库副本执行迁移，核对用户、角色、团队、客户、商机、跟进、周报、飞书配置和演示数据批次的行数及关键字段不变。
4. API、普通 Worker、飞书 Worker 和中台适配器分别核对版本，不能只替换 API 代码。
5. 任何 CRM 导入、模拟数据清理、账号调整和飞书发布都必须有单独回执；代码测试通过不代表真实数据已经迁移。

## 8. 实施顺序

1. 冻结当前神码版本，保存代码、数据库、运行配置和演示数据批次指纹。
2. 建立独立升级分支，先移植后端公共契约和数据库兼容层。
3. 在隔离数据库验证迁移、登录、权限和现有神码定制流程。
4. 适配小程序 UI、客户、商机、跟进、报告和飞书入口。
5. 接入 CRM 测试环境，完成字段映射、首次导入、增量同步和权限反例。
6. 用隔离演示公司完成销售、主管、销售总经理、运营管理员和中台管理员的端到端验收。
7. 生成神码专属源码包、版本清单、迁移清单、使用文档和回滚方案。
8. 取得验收结果后，再由神码运维在维护窗口备份、迁移和切换；本适配计划不自动执行生产发布。

## 9. 首批验收门槛

1. 原神码账号仍可登录，原角色和数据范围不扩大、不丢失。
2. 演示公司与正式公司隔离，模拟数据后台可筛选、可追溯、可安全清理。
3. CRM 首次导入不重复建档，CRM 编号、负责人、团队和阶段读回正确。
4. 客户、商机、跟进、周报和飞书同步的来源、权限和失败重试可读回。
5. 小程序和 Web 的金额、阶段、预测、实际、报告和错误提示口径一致。
6. 飞书多维表格、群通知和周报记录不写入测试数据，失败任务可重试且不重复推送。
7. 迁移前后用户、权限、客户、商机、跟进、周报和配置快照满足保护清单。
8. 生产切换前必须具备备份校验、回滚候选和明确的失败停止条件。

## 10. 当前不直接纳入上线的内容

1. 内部 1.2.1 中仍处于 M3 阻断状态的团队/成员范围、任务 V2 和长时间报告生成链路。
2. 未取得 CRM 正式接口文档、字段字典和测试账号前的真实同步写入。
3. 未经过神码角色验收的跨租户、全组织导出和管理员扩权。
4. 任何需要复制内部账号、模型 Key、飞书应用或业务数据的做法。
