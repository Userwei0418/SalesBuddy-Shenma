# 正式公司内的试用模拟数据

适用于 CRM 接入前，让现有业务账号体验客户、商机和后续跟进。模拟客户和真实客户共用既有公司、账号与权限，业务页面使用自然名称；来源只在销售后台标识。真实组织、密码、角色、团队及账号额度不因导入而调整。

## 数据与使用边界

- 每位在职销售一组客户、商机；主管和总经理按既有权限查看。
- 模拟商机金额会出现在业务页面及商机汇总中，不能作为真实销售预测或业绩。初始只提供需求、商机阶段、下一步计划，不编造历史跟进、签约、确收、回款或模型评分。
- 客户后台用途为“试用模拟”，`data_kind=demo`。`import_meta.synthetic_trial` 保存来源 `trial_seed`、完整批次和根客户 UUID；后续新增商机、跟进、待办继承来源。
- 试用内容不进入正式飞书多维表格及群通知、正式周报素材或销售能力评估事实。历史周报和已排队的发布也会重新检查来源。
- 来源标记不可被普通编辑清除。系统拒绝在一条跟进或待办中混合真实与模拟业务，或混合不同模拟客户的来源。确需转为正式业务时，应新建真实客户并核验事实，不能直接改用途。
- 未录入跟进、未完成评估的客户可以处于待评估状态；样例不预造评分。

## 后台识别

销售后台的客户列表可按“数据用途”和完整“试用批次”筛选。客户详情和导出表包含用途、批次，编辑表单只读展示。普通业务 Web 和小程序不添加“演示”等名称前缀。

## 导入维护

必须先部署 V159 及对应后端。维护脚本是 `scripts/synthetic_trial_data.py`，读取受限本地 JSON，数据文件不入公开 Git。实际公司、人员 UUID 和维护归属人从经核对的组织快照取得。

设置仅在维护环境可用的 `SYNTHETIC_TRIAL_DATABASE_URL`，然后执行 `plan`。命令参数必须显式提供 `--dataset`、`--workspace`、`--batch`、`--actor-user-id` 和 `--expected-sales`。

审阅计划后，将命令改为 `apply`。脚本核对当前销售与团队集合、完整批次、对象冲突，并在单事务内导入。重复执行完整未变的批次不会新增重复数据；部分存在、已有编辑或名单变化会拒绝执行。不得修改输入文件绕过这些保护。

## 后续清理

使用原始输入文件及相同参数执行 `cleanup`，默认只读，输出本批对象、关联内容和冲突。保存输入文件、清单、指纹与执行回执，不按客户名称或全库 `demo` 条件删除。

只有完整、未被使用或修改的批次才允许显式 `cleanup --apply --confirm-batch <完整批次>` 软归档。存在新跟进、待办、共享关系、用户修改或其他使用痕迹时，工具停止自动归档，需先逐项确定保留和迁移方案；不能强制级联删除。软归档保留主键、来源和关联审计，后续不再出现在正常业务列表。

## 验收证据

发布前核对来源继承、不可移除、跨公司隔离、正式周报及飞书排除、真实业务路径、导入幂等和清理拒绝条件。发布后保存实际导入清单、各销售可见范围、后台标记、身份与隔离演示公司前后指纹及健康检查。单元测试通过不等于线上导入完成，线上结果以当次受限交付回执为准。
