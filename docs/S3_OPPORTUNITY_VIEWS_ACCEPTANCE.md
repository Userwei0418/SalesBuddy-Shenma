## 操作说明

1. 电脑端销售工作区 → 商机。选择搜索词、团队、负责人、阶段、等级、产品线、关单时间及是否包含已关闭商机。
2. 在“显示字段”选择需要查看的列；“商机 / 客户”保留。可选择“季度与阶段 / 预计关单日期”排序和“按季度分组 / 不分组”。排序在服务端完成后再分页。
3. 点击“保存为新视图”，输入不超过 40 个字符的名称。当前公司、当前账号最多保存 100 个个人视图。
4. 选择已保存视图会恢复字段、筛选、排序和分组；“更新当前视图”保存调整，“重命名”只修改名称，“删除视图”只删除偏好。
5. 视图保存在服务器。加载或保存失败会显示错误，不把浏览器临时状态当成同步成功。重试沿用相同请求标识，避免重复保存。
6. 多个页面同时修改同一视图时，旧版本会收到冲突提示。先刷新并核对最新配置，再决定是否修改。
7. 已删除、损坏或不再适用的配置恢复默认显示并提示原因；重新保存完整有效配置后才修复。仅重命名不会替换原配置。
8. 小程序仍使用原商机筛选，本批没有新增完整的个人视图编辑界面。

## 权限与保留项

- 视图绑定当前公司和当前用户。其他销售、主管和管理员不能读取或修改他人的私人视图。
- 读取或修改视图均需当前 `opportunity.read` 权限；撤销权限后，包括旧请求回执重放也会拒绝。
- 视图筛选不授予额外业务权限。销售仍查看原有本人/参与范围，主管和总经理仍受原团队、公司授权约束。
- 团队编号、负责人编号即使被手工写入视图，实际商机查询仍执行原授权检查；越权团队返回拒绝，隐藏负责人的数据不会出现。
- 负责人筛选使用稳定 ID，保留旧姓名查询参数兼容；负责人选项只从当前已授权商机集合生成。
- 保留神码蓝色界面、账号、角色例外授权、额度、公司与演示数据标记、原飞书绑定、模型配置及原有商机字段口径。
- 每次更新和删除使用版本号与幂等键；数据库启用强制行级权限、归属不可变、版本递增和审计。

## 复跑入口

- 从仓库根目录运行，按 `backend/uv.lock` 安装开发依赖。`PYTHON` 指向该环境，`PGHOST/PGPORT/PGUSER` 只指定本机测试 PostgreSQL 维护连接。
- HTTP 回归：`"$PYTHON" backend/tests/system/verify_opportunity_views_api.py`。
- 并发/RLS：`"$PYTHON" backend/tests/system/verify_opportunity_views_postgres.py`。
- 升级保留：`"$PYTHON" backend/tests/system/verify_opportunity_views_upgrade.py`。
- API 契约：在 backend 目录设置 `PYTHONPATH=src`，执行 `"$PYTHON" scripts/export_openapi.py --check`。
- Web 构建与单测：`npm --prefix business-web run verify`。
- 浏览器：`node --test business-web/tests/opportunity-views-s3.browser.mjs`，需本机 Chrome/Playwright，可通过 `PLAYWRIGHT_MODULE` 指定既有模块。
- 本轮因 Documents 中旧依赖读取阻塞，使用相同源码与锁文件在 `/tmp` 构建和验收，未更改依赖版本。
- 所有数据库入口创建独立临时库和运行角色，完成或失败后清理；不向正式库填入验收数据。
