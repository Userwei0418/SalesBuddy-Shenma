# 神码 Web 1.2.1 新界面适配与后续能力清单

## 1. 本次范围与版本依据

用户在 S2 客户建档、S3 个人视图之后补充要求：神码 Web 迁入内部新版 UI，同时迁入配套业务能力，保留神码特性。实施顺序据此调整为先完成 S7A 新 PC 界面与已具备接口的业务适配；其余能力按依赖继续分批。

1. 神码本轮起点为本地 `20d8dc6`，包括 S2 `b72fb2e`、S3 `7a70182`。正式环境只读复核仍是 `094841a60c446d88febfdc199be5d0877424193a` / V159。
2. 新 UI 来源固定为内部 Web `e6099547ddaab0f1e4534c6216e7b9977e3c7368`。该版本已经包含 PC 2.0 导航、工作台、客户经营、商机工作区、跟进记录、工作报告等模块。
3. 内部 LOCAL `a3e6f39f0be11a298cd56bbd9d73615a52979a88` 仅在上述版本上修改 9 个文件，主要涉及 Review 多范围与报告轮询。本轮未复制内部脏工作区或未经配套验证的改动。
4. 内部事实源登记的配套后端是 `5c2dad4` / V250；不能把 Web 提交中保留的旧后端目录当作当前接口依据，更不能在神码直接执行内部迁移编号。
5. 本轮只在本机隔离环境改代码、测试。没有部署、正式数据库迁移、微信上传、正式飞书消息或模型调用。

## 2. 已接入隔离候选的新界面与能力

1. 新 PC 框架：浅色侧栏、可折叠分组、面包屑、紧凑顶栏、按权限显示的新建菜单、账号及后台入口；窄屏保留底部导航。
2. 工作台：快捷进入客户建档、商机、跟进、任务和周报；原任务概览与业务动态保留。新增跟进概览，按今日、本周、双周、本月、本季度及本人/部门/成员查看，支持下钻。
3. 客户经营：新版标题、指标卡、紧凑筛选、地图和列表布局、分页；建档申请及进度与认领保持独立，原始公司编号、团队和审批流程不变。
4. 商机：新版列表与工具栏、个人视图设置、字段显示与顺序、排序分组；继续使用 S3 服务端私人配置及原授权商机集合，失败保留、版本冲突和失效筛选提示保留。
5. 跟进记录：新增独立页面，按时间、人员、客户、商机或表格查看；日期与全文搜索、客户/商机筛选、摘要到完整详情、分页、失败重试及撤权后清除旧数据。
6. 跟进后端：新增只读 `GET /api/v1/visits/range`，按原 `visit.read` 与 RLS 查询，所有人员、团队、日期条件只缩小范围。同一条记录关联多个商机不重复计数，关联不同客户时保留各商机的客户编号。
7. 周报：接入新页面标题、面板、密度和视觉；保留神码现有 14 天素材、生成任务、草稿编辑、历史版本、取消、冲突恢复及确认后飞书入表和群推送。
8. 任务、客户/商机详情、跟进录入和后台仍复用已有功能与状态机，应用新主题；本轮不把内部新状态或新接口隐藏地混入这些流程。

## 3. 神码必须保留的特性

1. 正式公司、隔离演示公司、人员、团队、账号、角色、自定义授权与例外授权。原手机号、`smAdmin` 和演示短用户名继续使用原认证方式。
2. 正式部署 65 个启用业务账号额度及独立演示额度。本轮没有回放历史额度 SQL，没有调整配置。
3. 统一模型 Key 的运维入口和操作者限制，完整 Key 不回显。中台模型连接锁及各用途绑定不改变，不复制内部 Key。
4. 跟进和周报的神码飞书 Base、表、群绑定、发布版本及幂等记录，不复制内部机器人、群、表或账号。
5. 演示数据的后台来源标记、继承和正式推送排除规则；业务页面不添加体验前缀；原有可见性、归属及后续清理依据不变。
6. 神码主色 `#2863CD`、客户 AppID `wx2824bdeb58528fd8`、现有域名和路径。新浅色布局采用内部 PC 2.0，登录和侧栏显示神码身份。
7. S2 审批通过后仍待认领，S3 仍为本人私人视图；界面变化不扩大业务数据范围。
8. 新成员筛选沿用神码已有 `directory.read` 候选目录，实际跟进范围由服务端裁剪。目录不是精确的跟进统计人口，因此本轮不显示据此推算的人均或“零跟进成员”。
9. 全局与列表“新增商机”入口保持神码原定制关闭；工作台提供商机列表入口。原八字段商机详情、元值金额及未确认字段空值展示保留。

## 4. 需要继续配套迁移的能力

1. 客户全量经营视图及统一申请历史：内部依赖 `/customers/portfolio`、`/customers/requests/history` 和企业身份字段。神码当前保留原客户集合与 S2 申请记录，不能用一个名称相近的接口替代新合同。
2. 完整商机工作区：内部需要视图 query/preference、结构化字段编辑、项目人员管理与商机人员目录。神码 S3 是 v1 私人配置；后续需设计兼容升级和旧视图转换，再增加 v2 查询和编辑能力。
3. 财务与预测：按 S4 先对齐神码业务口径，再补接口和 UI。不能将内部 ACV、确收或回款公式当作神码已确认口径。
4. 工作报告 V3：日报、双周报、月报、季度报、章节方案、快照、共享导出和会议视图依赖新的后端持久化与 Worker；迁入时必须继续承接神码原周报历史与飞书发布。
5. Review/OKR 及新任务协作：按独立后端、数据库和角色验收接入。内部事实源仍有真实模型生成、常驻 Worker 及部分多范围链路未闭环，暂不作为神码可用能力。
6. 新任务和风险筛选：神码同名旧接口会忽略部分新参数；必须先补服务端筛选和真实回归，再开放对应 UI。
7. 知识库：需要神码自己的产品、方案与定价资料；不直接复制内部静态知识目录。
8. CRM：等待集团接口文档、字段字典、测试环境及权限；继续按首期只读客户、商机、人员和组织的既定范围实施。

## 5. 验收和发布边界

1. 每个增量分别记录源码、构建、真实 HTTP/数据库、浏览器、原生小程序、正式部署和客户业务验收。
2. 新 UI 浏览器使用本机合成接口并阻断外部请求；实际数据权限由独立受限 PostgreSQL/HTTP 回归证明，两种证据不能混称一次线上验收。
3. 本轮新跟进接口无需新增数据库迁移；配套候选仍是神码 V161。已有 V160/V161 仅在隔离库演练。
4. 进入正式发布前，仍需固定最终包、备份及恢复验证、配套服务和真实业务试用回执。此文不表示新版本已上线。
