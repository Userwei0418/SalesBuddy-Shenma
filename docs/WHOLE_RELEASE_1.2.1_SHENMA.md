## 数据库升级方法

原 V152–V161 的编号与内部不同内容冲突，因此保留原客户迁移和 checksum 账本，新增 V299 前置兼容、V300–V398 上游迁移桥接及 V399 神码规则恢复。上游缺号保留，不虚构执行记录。完整映射与来源 SHA 以 database 中的桥接清单为准。

发布前以服务器 pg_dump 一致性副本迁移，比较原有列内容摘要、行数、密码哈希与配置；重复迁移应全部 unchanged。验证副本仅监听回环地址，不启动通用 Worker 或飞书 Worker，不消费复制过来的历史任务。报告验收只执行精确指定的本次新任务。

正式切换前再次停止写入、备份数据库/上传文件/运行配置/密钥，验证备份可恢复。升级脚本要求成功的副本迁移回执，校验发布包 SHA、当前版本和实际 schema；失败时保留失败库并恢复已验证的升级前副本和原程序。
