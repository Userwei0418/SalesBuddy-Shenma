# 神码双端验收与本轮修复

本轮在神码独立测试公司使用虚构演示资料，微信开发者工具、业务 Web 和管理端连接客户公网 API。生产部署回执、完整截图与演示台账随 `shenma-1.0.9-20260927` Release 和本次本地交付包保存；下表区分代码验证、真实业务验证与仍需手机完成的部分。

## 验收中发现并修复

| 问题 | 修复及验证 |
|---|---|
| 11 条真实归档的演示素材生成周报时，4096 Token 输出额度在 JSON 中途耗尽 | 保持原提示词与结果校验；使用同一冻结输入证明 senseaudio-s2 在 16384 额度下可完整返回，实际输出 6111 Token、44 秒，结构及引用校验通过。通过中台正常 API 提高模型声明允许上限并仅发布周报 Agent 的 16384 额度，其余 12 个 Agent 配置与快照逐项保持一致 |
| 周报输出拒绝后丢失已成功调用的中台回执 | 保留 message/conversation/task ID、Token 用量和固定错误分类；不保存未验证正文或任意 JSON 字段名，不自动重发。12 项数据库集成通过，覆盖错误 JSON、统计不符、未知字段、取消、幂等、草稿冲突和跨账号权限 |
| 手机 Web 客户页地图和列表被裁掉 | 取消手机布局容器的尺寸隔离，让内容决定高度；验证地图和列表实际可见、可点击 |
| 手机风险表文字被挤成竖排、长面包屑覆盖正文 | 风险表在自身区域横向滚动，保留所有列和点击操作；手机面包屑单行省略。1440/390 宽度及双向 resize 浏览器回归通过 |
| 部署器拒绝已是 V153 的后续代码更新 | 支持 V153 → V153，操作主机/目录/服务前拒绝结构降级；保留备份恢复、数据保留、迁移幂等和健康检查流程 |

## 已取得的证据

- 核心演示批次：10 客户、12 商机、20 归档拜访、14 待办。拜访经过真实结构化、质检、确认归档；保留一次 55 分被拒绝的原记录及补充材料后重新提交的恢复过程。
- 小程序：真实登录、销售/主管/总经理页面、团队范围及季度筛选、文字拜访归档、自建待办完成、新增商机和详情回读。域名校验开启，实际访问客户公网。追加 1 拜访、1 待办、1 个 1000 元商机，均明确标为演示。
- Web：带数据客户/商机/拜访/风险/地图/看板页面，桌面与手机宽度；跨人待办的派发、接受、提交、主管退回、销售重提、主管确认及刷新回读。多负责人各生成独立待办，追加 2 条，不改变预置待办状态。
- 管理端：18 模块实际加载、刷新续登、退出、手机导航。认证/权限 68 项检查通过，包括跨公司访问拒绝和退出后凭据失效。
- 上传与转写：文本上传、原文下载字节一致、跨销售访问拒绝、非法/空文件拒绝、合成录音直接转写和 Worker 文件转写，共 14 项通过。合成音频的专名存在同音字，须人工核对。
- Web 构建与合同测试 134 项、移动布局浏览器测试 2 项通过；完整仓库 CI 以 Release 所关联提交的成功记录为准。

## 发布和验收边界

演示公司独立于真实业务公司，但当前业务 API 使用正常数据类型，演示识别依赖测试公司、明确名称和批次台账，不能宣称系统自动排除演示统计。拜访沟通日期覆盖过去两周，上传时间均由服务器产生，未伪造历史上传时间。

扫码预览、开发者工具验收、体验版上传和微信正式发布是不同阶段。真机麦克风、录音中断恢复、实际文件选择上传与微信审核状态，须以本次交付回执中的实际结果为准。财务实绩写入、目标审批、飞书/CRM 外部同步及每个角色所有写操作，不因页面能渲染而视为全部通过。

新增商机五字段、跟进类型和关联业务仍等待确认的业务映射；ChatBI 首页入口当前未开放。未为了验收临时开放功能或绕过后台权限。中台运行 API 未提供实际快照证明，`expected_snapshot_id` 仅是配置记录，继续保持 `runtime_snapshot_verified=false`。

新版本发布前使用 `npm --prefix business-web run verify` 和浏览器回归，提交后重新构建打包；现场核对当前 SHA 与 V153，保留数据库、上传目录及配置备份，实际恢复校验后切换 release。部署后须在客户公网复验周报 ready/编辑保存、手机客户页和风险详情，成功回执再归入 Release。
