# SalesBuddy Web 协作约定

本仓库保留 Web 0.6.12 展示工程，当前业务基线已同步为小程序 1.0.9（2026-09-25）。本轮前端范围、证据和正式联调边界见根目录《修改交接文档.md》。先用 `git status` 确认当前分支和改动；每个交互方案单独开发，交回 PR 供比较，合入由用户决定。

## 修改顺序

1. 先找对应 `source/miniprogram/pages/` 及 `utils/` 的字段、权限和处理事件，再修改 Web 布局。改设计时读 `docs/cloud/design-standard.md`；出方案或交接时读 `docs/cloud/review-handoff.md`。
2. UI 使用根目录样式、`scripts/web_*_layout.py` 和现有适配器。`dist/` 是生成目录，执行 `npm run build` 更新。`source/manifest.json` 校验共享源，保持原文件和清单一致；不要通过改哈希绕过业务源码漂移检查。
3. 使用 `npm run preview` 跑合成示例；页面地址必须带 `?mode=preview`。云端 UI 任务不依赖真实账号、CRM 文件或 Agent。示例检查不证明真实接口写入。
4. 交付前执行 `npm run verify`；有页面交互改动再运行对应浏览器检查，记录视口、结果和未验证项。只跑了构建时如实写构建通过。无法运行的检查写原因。

## 保持一致的业务含义

- 客户认领是申请后审批；提交成功不代表客户已归属。
- 任务通常是提交完成说明后由发起人确认／驳回，自建自领沿用直接完成规则。
- 拜访保留核对、质检、人工确认、归档；修改内容后旧质检失效。
- 下一步行动与正式任务分开；待办建议采纳仍须确认任务字段，FDE与其他权限边界沿用原处理。
- 客户、商机、任务、拜访是不同对象；服务端 capabilities 决定操作权限。ACV、确收、回款分开，缺失不伪装成零。
- 选项、团队目录与稳定 ID 沿用后端契约。展示优化不隐含改变状态机、API、必填或统计口径；确需改变时单列影响，与小程序一起对齐。

## 页面与回传

页面称“总览”。桌面优先清晰分区和紧凑列表，按内容决定两栏或三栏；首屏能开始主要工作，保留长内容查看和窄屏操作。用 `design-tokens.css`、SalesSelect、SalesDatePicker，复用现有组件，不将迁移技术框架混入交互任务。

### 来源工程的部门组件库候选分支（2026-09-20历史说明）

用户已要求基于部门装包提示词制作一版，当前 `codex/department-design-20260920` 因此单独接入 React18、Ant Design6/X2 与 `@shandiant` 组件，限总览、客户列表与象限图、任务列表、创建任务四页。该范围用 `department-ui/` 的展示适配，不另外实现 API/权限/状态机；其他页面仍走已有渲染器。它是上一段技术边界在本候选方案中的明确例外，不代表全站框架迁移获批。特殊首页语音/ChatBI状态、客户详情/点位画像交还原渲染器。具体契约、包版本、已测与未测项见 `docs/cloud/department-design-20260920.md`。

首次运行 `npm ci --ignore-scripts`；候选预览用 `npm run preview:department`，默认5188。构建同时生成 React 资源，不能只运行旧的 Python 构建脚本。`package-lock.json` 必须跟随依赖变更提交；不要提交 node_modules、dist、真实账号或数据。UI 包里的跨端新增 token 仍是草案，不据此更改已确认的业务含义。

回传：解决的问题、改动页面和文件、前后对比或截图、业务影响、实际测试、剩余问题。加载、空、错误、无权限及表单失败恢复需按适用场景覆盖。凭据、真实数据、缓存和历史截图继续保留在仓库外。

跨机运行与 Claude 云端设置见 `docs/cloud/claude-cloud.md`。本机协作中心并非云端依赖；云端用仓库分支、PR 和交接记录协作。
