# SalesBuddy Web 设计规范 V1

**目标：让销售一眼看清重点、找到下一步；让产品、前端与 AI 用同一套规则交付。**

本版依据用户批准的《SalesBuddy Web 设计规范 V1 整理计划》，适用于销售 Web。小程序共享业务术语、事实、权限和状态含义，分别采用适合端侧的布局。当前页面截图是验证资料，规则以本规范为准。

## 从这里开始

| 你要做什么 | 使用方式 |
|---|---|
| 设计新页面 | 先选择 T-01～T-05 模板，再引用组件与业务规则 |
| 开发页面 | 复用共享样式变量和现有选择器；用示例册确认反馈 |
| 验收页面 | 按 [验收清单](checklist.md) 逐项检查并记录证据 |
| 看实际效果 | [可交互示例册](http://127.0.0.1:5187/design-system/index.html)；普通 Web 本地服务也支持 5186 端口 |
| 查本轮结果 | [实现与验证](baseline.md) |

示例册是合成数据交互演示，未连接登录、业务 API、真实 AI 或数据库；其中页面模板用于说明布局，不能作为可直接接入后端的完整业务页面。Tom Select 和 Flatpickr 使用与产品相同的适配器，ECharts 使用同一份库。

**状态分层：** 已确认 = 本版批准的规则；已实现 = 本地代码具备；已验证 = 有对应检查证据；待整改 = 现有产品页面尚未完全遵循。建议规则须标明“建议”，不能覆盖已确认规则。本版下表均为已确认规则，实现覆盖见验收清单。

**2026-09-20 用户明确调整：** 常规页面不再常驻统计口径解释、操作教学、重复副标题和模板化动态摘要。指标以名称、数值、单位呈现，筛选范围通过分区名称和已选条件表达；口径帮助可按需打开。完整业务正文、变化事实、风险依据、权限/错误反馈及操作确认保留。此要求适用于部门组件页与原展示层；具体实施见[页面文案精简](concise-page-copy-20260920.md)。

## 1. 设计原则

| 编号／场景 | 具体要求 | 正确示例／反例 | 验收方法 |
|---|---|---|---|
| P-01 所有页面 | 先呈现对象、重点状态与主要动作；摘要后可看完整事实 | 正：商机名称＋需关注＋变化摘要；反：所有信息同字号同权重 | 首屏能回答“这是谁、发生什么、下一步做什么” |
| P-02 多区域页面 | 用标题、留白、面板边界区分总览、操作、结果；每区一个主要动作 | 正：首页待办与动态独立；反：一长列同质卡片 | 隐去内容后仍能辨认分区；操作归属明确 |
| P-03 连续操作 | 失败、取消或切换展示时保留有效输入；处理反馈与事实状态分别表达 | 正：质检失败可回到原文；反：一失败就清空 | 填写长文本后制造校验失败，内容仍完整 |

## 2. 视觉基础

### 2.1 共享变量（唯一代码定义）

源码：[design-tokens.css](../../design-tokens.css)。产品和示例册均在组件样式前加载。现有 `--ui-*` 变量名与生效色值保持兼容；不得在页面内重新定义整套全局主题。

| 用途 | 变量 | V1 值 |
|---|---|---|
| 深蓝导航 | `--ui-sidebar` | `#142F54` |
| 工作区背景／内容面板 | `--ui-background` / `--ui-surface` | `#F3F5F9` / `#FFFFFF` |
| 主要操作／悬停 | `--ui-primary` / `--ui-primary-hover` | `#2863CD` / `#2055B5` |
| 正文／次要文字／辅助文字 | `--ui-ink` / `--ui-secondary` / `--ui-muted` | `#192842` / `#5B6C82` / `#617188` |
| 边界／选中／焦点 | `--ui-line` / `--ui-selected` / `--ui-focus` | `#E2E8F0` / `#EDF3FF` / `#5786DC` |
| 红色文字／底色 | `--ui-danger` / `--ui-danger-soft` | `#A73F38` / `#FBE4DF` |
| 黄色文字／底色 | `--ui-warning` / `--ui-warning-soft` | `#805919` / `#FFF0CF` |
| 绿色文字／底色 | `--ui-success` / `--ui-success-soft` | `#27694C` / `#E8F5EE` |

| 编号／场景 | 具体要求 | 正确示例／反例 | 验收方法 |
|---|---|---|---|
| V-01 配色与层级 | 深蓝导航、浅色阅读、白色面板；蓝用于动作和选中；业务状态色配文字或图标 | 正：红色边线＋“转差”＋依据；反：大面积深色正文区或只显示色点 | 颜色与标签含义一致；文字在背景上可读 |
| V-02 字体与数字 | 系统中文字体；正文 14px、辅助 12px、分区标题 16px、页面标题 24px、关键数字 32px；正文行高 1.65，标题 1.5；数字等宽对齐 | 正：标题、事实、时间分三层；反：一整段任务说明加粗作大标题 | 长中文与大金额不覆盖状态、按钮；关键内容不因截断丢失 |
| V-03 间距与形状 | 间距 4/8/12/16/24/32px；控件圆角 6px、面板 12px；普通控件高 36px、表单 40px；同组紧密、分区疏朗 | 正：列表条件与结果间 12～16px，独立面板间 24px；反：所有空隙等宽 | 对照示例册；偏离时记录具体理由 |
| V-04 图标与焦点 | 图标延用产品已有风格；常用图标 16px；纯图标按钮提供可读名称；键盘焦点轮廓至少 2px；正文正常状态对比度目标 ≥4.5:1 | 正：刷新图标有“刷新”名称；反：依靠颜色猜按钮 | Tab 可见，读屏名称明确；检查常用文字与状态标签对比度 |

间距变量：`--ui-space-1/2/3/4/6/8`；尺寸变量：`--ui-control-height`、`--ui-field-height`、`--ui-radius-control`、`--ui-radius-panel`。新组件优先使用变量，旧页面按整改项渐进迁移，不批量替换所有业务样式。

## 3. 通用组件

| 编号／场景 | 具体要求 | 正确示例／反例 | 验收方法 |
|---|---|---|---|
| C-01 按钮 | 同一区域突出一个主操作，次操作描边或文字；默认、悬停、聚焦、禁用、处理中均有表达；禁用说明原因 | 正：“保存中”并阻止重复提交；反：三个同样抢眼的主按钮 | 鼠标、Tab、Enter 操作；处理中不可重复提交 |
| C-02 输入与校验 | 标签常显，必填项明确；错误就地提示并关联字段；错误时保留输入；仅对应处理阶段只读 | 正：沟通内容缺失时提示且保留下一步计划；反：用 placeholder 代替标签 | 中文输入、长文、粘贴、失败重填；不可覆盖正在编辑的值 |
| C-03 选择器 | 使用现有 SalesSelect、SalesDatePicker；搜索、多选与清空可用；单选选中即生效，多选点击应用；Esc 取消，焦点回触发点 | 正：季度多选显示已选数量；反：四个季度用庞大双栏弹窗 | 搜索无结果、取消、多选应用、日期合法性、窄屏位置 |
| C-04 筛选栏 | 紧邻所属结果区，注明作用范围，显示已选条件、结果数和清除入口；总览与列表分别命名 | 正：“商机列表·阶段”，上方总览保持不变；反：无标题下拉放在两个区域之间 | 改列表条件核对总览；改统计周期核对列表；清除恢复 |
| C-05 列表与表格 | 名称、状态、负责人、时间、金额、操作位置稳定；长文可展开完整内容；不以卡片堆叠替代桌面列表 | 正：首行对象、次行摘要、末列操作；反：长标题把状态推离屏幕 | 长名称、20 行以上、空列表、窄屏；操作可达且关联对象正确 |
| C-06 数据与反馈状态 | 加载有文案；空数据说明原因及下一步；异常可重试；部分缺失应显示已有数据并说明覆盖范围 | 正：未登记回款；反：加载失败显示 0 | 切换正常、加载、空数据、异常；重试不丢筛选 |
| C-07 弹窗与展开 | 标题清楚；弹窗有关闭与取消；Esc 可关，焦点不逃逸且关闭回到触发点；次要详情优先就地展开 | 正：摘要后展开完整判断依据；反：看一行备注也跳新页面 | Tab/Shift+Tab、Esc；展开不改变记录、顺序、业务状态 |

### 复用入口

- 选择器：[select-components.js](../../select-components.js)，`SalesSelect.open({anchor,title,description,options,selected,multiple,commit})`。产品页面延用已有 `owner` 与业务回调。
- 日期：[date-picker.js](../../date-picker.js)，`SalesDatePicker.open({anchor,mode:'date',value,onCommit})`。取消不回写。

## 4. 页面模板

示例入口使用固定锚点，便于在需求与验收中直接引用。

| 编号／场景 | 具体要求 | 正确示例／反例 | 验收方法／示例 |
|---|---|---|---|
| T-01 总览 | 待办、常用操作、业务动态独立；动态按对象、摘要、状态、时间、动作组织；红黄业务判断进入“需关注” | 正：需关注来自业务判断；反：橙色任务“待接受”当作商机风险 | 全部／需关注切换、展开依据、完整标题可读；[#template-home](http://127.0.0.1:5187/design-system/index.html#template-home) |
| T-02 业务列表 | 总览独立面板；列表标题、工具栏、条件、数量和结果同区；局部筛选不污染其他区域 | 正：列表无匹配时总览仍显示原统计；反：全页一个含糊的时间选择器 | 搜索＋多选组合、单条件移除、清除；[#template-list](http://127.0.0.1:5187/design-system/index.html#template-list) |
| T-03 经营详情 | 对象摘要与主要操作在顶部；页签组织摘要、跟进、任务；主栏事实、辅栏关注与依据；客户与商机分开 | 正：商机注明所属客户；反：把客户整体与某商机状态混为一谈 | 两种对象切换、页签键盘操作、完整记录；[#template-detail](http://127.0.0.1:5187/design-system/index.html#template-detail) |
| T-04 拜访录入 | 桌面左右分栏，关联对象与编辑内容同屏；长文本内部滚动，操作区固定在表单底部；窄屏上下排列 | 正：失败保留下一步计划；反：长页面滚到底才能提交或静默失去草稿 | 1024×600、长文本、必填缺失、返回修改；[#template-visit](http://127.0.0.1:5187/design-system/index.html#template-visit) |
| T-05 经营分析 | 范围／周期紧邻指标；金额、数量分别标单位；图表配数据表、空值与统计口径说明 | 正：缺关单日期的条目明确标注未纳入；反：缺数据的指标算 0 | 切季度图表与合计一致，缺失仍缺失；[#template-analytics](http://127.0.0.1:5187/design-system/index.html#template-analytics) |

适配：>900px 优先桌面布局；601～900px 收紧布局，保持操作可达；≤600px 改单栏，必要的宽表仅在表格内横向滚动。完整页面不得水平溢出。示例册本身允许自然纵向阅读，不把文档页强制压成一屏。

## 5. 业务表达

| 编号／场景 | 具体要求 | 正确示例／反例 | 验收方法 |
|---|---|---|---|
| B-01 红黄绿灰灯 | 业务变化使用红“转差”、黄“需关注”、绿“向好”、灰“待评估”，同时呈现判断依据；沿用业务来源结果，不从颜色、关键词或缺失字段推断 | 正：更新成功但判断未返回显示待评估；反：所有保存成功一律绿色向好 | 使用四类业务返回检查标签、摘要、依据及关注计数；技术保存成功不冒充业务判断 |
| B-02 对象与状态 | 客户、商机、拜访、任务各自有事实来源；任务已接受仍未完成；下一步计划未创建任务前不计入任务 | 正：“已接受，待执行”；反：“接收方已确认”配已完成 | 查看实际状态字段与持久化记录；不能仅凭展示推断完成 |
| B-03 金额、时间与缺失 | ACV、确收、回款分别标注；0 仅用于明确零值；缺失显示未填写／未登记，处理中显示加载；金额有币种单位，完整日期带年份，动态时间展开可查 | 正：¥ 0 与未登记并列；反：用导入当天补齐所有关单日期 | 对照源数据；大金额和跨年日期无歧义；缺失不得臆造 |
| B-04 AI 流程 | 核对内容→质检→人工确认→归档；处理中可见阶段；失败保留输入且可重试或返回；超时走已有恢复机制；质检完成不等于归档 | 正：“已生成建议，待人工确认”；反：“AI 正在分析”时让用户误以为还能填写被锁字段 | 草稿、处理中、失败、待确认、归档各自回读；仅真实归档回执可显示已归档 |
| B-05 范围与权限 | 范围名邻近数据；权限与 capability 以服务端契约为准；前端隐藏按钮不等同于权限校验 | 正：“本人／团队”对应同一授权范围；反：依靠角色名称猜写权限 | 核对列表、详情和操作返回的权限；示例册合成数据不算权限验证 |
