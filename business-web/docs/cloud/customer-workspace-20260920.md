# 客户页空间与视觉优化

用户指出指标、筛选与结果布局松散，并明确要求四象限铺满下方留白；完成后提供交付包。

## 本轮方案

1. `department-ui/Customers.jsx`：将资产合并为紧凑横条，周期与帮助靠右；搜索和全部可用筛选整合进结果工作区，简化重复标签。
2. `department-ui/customers.css`：工作区内左图右表，四象限宽度约 36%，随内容区高度伸展到底部并与列表对齐；窄屏恢复上下排列。
3. 根据表格实际可用高度决定本地分页行数，保留分页、完整记录展开和筛选重置。原四象限视觉、坐标及点击处理不变。
4. 保留原资产口径、所有角色和目录权限、错误重试；共享小程序源码不改。
5. 构建、客户现有浏览器回归与经理长列表/窄屏验证通过后，将源码、构建页面和中文启动说明打成 ZIP。排除依赖目录、仓库历史、凭据、运行缓存与真实数据。

## 验证

重点检查 1366×768、1440×900、1024×600 和 390×844；经理六项筛选、四象限铺满、分页随高度变化、长文字完整查看、翻页及详情往返。合成数据检查不代表真实业务写入验收。

## 已实现与实测

- 资产区合成一条白色指标栏；本年/历年及统计口径入口靠右。移除页内重复刷新，继续使用顶部全局刷新。
- 桌面双栏将四象限调整为约 36% 宽度，给分区标签和客户点更多空间；右侧列表仍保留分页、风险状态和操作列。
- 搜索、象限、计划、优先级、金额及按权限出现的团队/成员放进共同工具栏。1366px 经理视角可在一行呈现，较窄窗口自然换行。
- 图表不再固定方形和最大高度，随工作区伸展到底部；原四象限颜色、坐标与点击处理保留。
- 列表按实际剩余高度分页。267 条合成目录在 1366×768 显示 5 行，在 1440×900 显示 8 行；1024×600 短屏自动减少行数，分页仍可见。缩放后保留原首条记录所在页。
- 客户名称、风险和团队长内容收进展开行；FDE 完整协助名单在展开行可查。普通列表不再由长内容撑高，展开时允许内容区滚动。390px 下恢复纵向布局。

构建通过（26 页、14 个原组件，256 份共享业务源哈希未变化）；117 项默认单元/契约检查通过。客户及总览相关浏览器用例共 12 项通过，覆盖角色、下钻、地图/列表联动、资产独立口径、空团队重置、详情往返、重叠点和经理/FDE长列表缩放。新增两项长列表用例检查普通行无纵向溢出、分页可见、全部267个点保留、完整内容展开。
