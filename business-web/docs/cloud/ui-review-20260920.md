# 2026-09-20 界面评审实施与验收

## 目标

依据用户提供的《小浣熊 SalesBuddy 界面评审》，让现有 Web 的列表、表单、反馈遵循既有 V1 规范；保持小程序 1.0.6 的字段、权限、校验、状态机和接口不变。独立分支交回 PR，合入由用户决定。

## 实施计划

1. A-1/A-2/E-2：通过 Web 布局适配器将两种商机列表统一为共享列头、紧凑行与末列操作；认领不可选项显示清晰的不可选状态。保留完整金额、日期、对象与权限。
2. C-1/C-2/C-3：客户建档将可安全复用现有编辑处理的字段内联；任务按类型、描述、负责人、优先级、截止时间阅读；新增商机优化选客户前后的表单占位与结果呈现。
3. A-3/E-1/E-3/E-4/E-5：收紧总览、详情和拜访的标题/指标；统一分析卡片；改正头像、重复文字、筛选提示和就近禁用说明。
4. B-1/D：统一交互反馈、键盘焦点、短过渡与 reduced-motion，新增样式契约检查约束本轮新增样式。沿用现有 tokens；旧样式渐进迁移，不进行全站机械替换。
5. 运行构建、单元和相应浏览器检查；验证桌面、短屏和窄屏的操作可达性，记录截图与未覆盖范围。

主要文件：scripts/web_*_layout.py、页面 CSS、design-tokens.css、Web 展示适配器、tests/。source/miniprogram 与 source/manifest.json 不变。

## 建议取舍与风险

- 批量验收任务需接口、逐条权限和部分失败契约，本轮不添加批量写入。
- 金额保留原精度和缺失含义；图表不从金额推断风险，不更改象限/点选业务。
- 不添加没有数据来源的本周待跟进、最近访问或默认推荐；不以装饰填空。
- 零结果筛选仍允许切换，避免形成无法返回的状态；次要操作保持键盘、触屏可达。
- 字段内联若无法通过现有处理完整维持校验，保留原编辑器并改进入口，不绕过业务校验。
- 不直接把所有间距替换成同一尺度：现有规范明确要求渐进迁移；仅收敛本轮涉及的页面。

## 验证范围

本地合成预览（无真实账号、CRM、Agent 或业务 API 写入）。先 npm run verify，再运行受影响的页面与流程检查；桌面 1440×1000、短屏 1024×600、窄屏 390px，并核对业务源码校验。实际结果在完成后补入。

## 未直接采用的建议

- B-2 批量确认；B-1 n/j/k 快捷操作：本轮保留逐条处理。批量写入需确定逐条权限、部分失败与验收规则；全局导航快捷键还需草稿保护设计。
- A-3 填充本周待跟进/最近访问：没有对应数据契约，不编造推荐。
- D 全量替换181种颜色与所有非标准间距：V1要求渐进迁移，本轮只约束新改样式；旧样式仍有技术债。
- E-3 金额统一整数、低频柱图改总结句：金额精度保留，图表和明细入口保留；未新增业务警示阈值。
- E-5 象限点用ACV/风险重编码、零计数筛选禁用：保持小程序的图表与筛选语义；避免用户无法切回空分类。
- E-5 任务标题与要求相同时自动删除内容：保留原任务描述，避免隐藏完整要求。
- 全量CRM性能复核：本轮未使用私人CRM导出；已验证原分页与滚动，不把合成示例结果当作万级数据性能验收。

## 复验入口

```sh
npm run verify
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node --test --test-concurrency=1 tests/ui-review-*.browser.mjs
```

浏览器检查使用已安装的 Chrome 与 Playwright。除注明真实接口的专项验收外，不连接后端；本轮全部为本地合成数据。`npm run preview` 启动独立示例服务，默认端口5187。

### 评审预览与企业登录入口修正

评审服务原先关闭了后端，却仍展示企业登录入口，导致提交登录后显示“尚未配置后端连接”。现在启动器显式声明 `previewOnly`：前端启动前读取本地服务能力，隐藏企业入口；误入企业登录链接时，提示返回示例体验，不启动企业登录。普通业务服务仍保留企业登录和示例模式切换，不根据“未配置后端”推断服务用途，也不硬编码本机端口跳转。

验证：构建与原104项单元检查通过，新增服务能力单元检查通过；原登录/模式切换13项、新增预览边界6项浏览器检查全部通过（1440px、390px，原回归另含320px）。预览全程无企业API或快捷登录请求。本机已单独检查企业服务可达，未代用户登录。

本轮遵循既有规范，未变更V1规则或发布新业务版本。分支方案待评审合入，既有0.6.12 ZIP保持原样。
