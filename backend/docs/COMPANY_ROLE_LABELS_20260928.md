# 公司岗位显示名称与旧小程序金额过渡

本轮用户确认“客户经理”仅用于演示公司及对客文档。实现不按公司名称判断，也不新增权限角色；本轮发布后只为经核对的原演示公司设置该显示值，真实公司保留默认称呼。

## 公司岗位显示名称

- `platform.workspace.attributes.business_role_labels.sales` 只接受 `一线销售` 或 `客户经理`，省略时为 `一线销售`。空白、非字符串、其他字段和值均拒绝；显示值不参与授权。
- `sales` 身份的有效任职部门全部是 `product_sales` 时，登录身份显示“产品销售”；同规则下 `supervisor` 显示“产品销售主管”。混合部门保留普通销售/主管称呼；组织页按每一条部门任职显示，不丢失兼任信息。
- FDE、FDE主管、运营、系统管理员和总经理身份原样保留。`role`、数据范围、权限、账号额度、业绩和团队成员统计不变。
- 后台“账号与组织 → 公司管理 → 岗位显示名称”可配置；按钮取 `company.update` 权限。登录、令牌刷新、`/auth/me`、组织页和任务负责人目录读取已授权公司的名称；小程序首页、个人信息和任务创建使用服务端名称。
- 仅称呼变化时，小程序更新当前页面名称，不清空未提交表单，不模拟权限改变。

接口：

1. 已登录并确认当前公司 UUID 为演示公司后，`GET /api/v1/console/companies/role-labels`，需 `company.read`；返回 `{"labels":{"sales":"一线销售"},"version_no":N}`。
2. `PUT` 同一路径，需 `company.update`，带唯一 `Idempotency-Key` 及 `{"labels":{"sales":"客户经理"},"version_no":N}`。
3. 重读公司版本、组织目录及一个销售账号的 `/api/v1/auth/me`。确认角色代码仍为 `sales`，显示值是“客户经理”；另读真实公司确认仍为“一线销售”。
4. 使用公司版本号防止覆盖并发名称/显示配置修改；同一请求重试返回原回执。操作记录为 `company.role_labels`，只记显示配置，不记录密码和令牌。

该配置利用已有字段、RLS 和审计，不新增迁移，不批量修改现有公司。新开户的 `demo_template` 与历史演示公司相互独立，模板不重置或复制现有演示业务。本补丁未开通或重置账号；`CPXS003/CPXS004` 应在发布阶段先查重，再通过现有账号管理入口建立普通 `sales` 任职，现有 `CPXS001/CPXS002` 主管任职保留。

## 1.0.9 与大额确认

维护窗口内配套部署后端和新版小程序体验版。金额达到本公司阈值（默认 1,000 万元）且未带准确确认值时，新后端继续返回 422，不创建、更新或重试正式金额写入。不降低阈值，不替用户自动确认。

冻结的 1.0.9 原始客户端与商机页提交函数已在隔离新 API 验证：422 中文正文会显示在页内错误区域，大额保存不导航、不自动重试，当前页面中的表单值仍在。普通低额创建/编辑继续可用。

**旧独立商机表单没有持久化草稿，退出小程序前必须复制保留填写内容；不能承诺退出升级后仍能恢复。** 旧拜访确认页有本地草稿，失败分支不删除草稿；这与独立商机表单是不同的保存路径。后端错误提示明确先复制保留内容，再从新版体验版入口重开，或由本公司有权限的管理员在后台核对、确认并保存。服务端不能强制刷新已经驻留的微信客户端。

该机制不代表微信真机更新已完成。真实体验版仍需在发布后核对版本和确认弹窗；低额、金额不变编辑和大额确认取消/保存分别验收。
