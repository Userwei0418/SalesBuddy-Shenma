# 周会任务中台与调用日志补修（2026-09-28）

## 问题与修复

周会导入首次真实调用失败后返回了规则草稿；相同原文再次预览复用了旧草稿。AI 调用管理未登记 `task_import` 等业务名称，私有推理审计结束时又因 API 无表 SELECT 权限而拒绝原有直接 UPDATE，导致部分历史记录一直显示运行中。

本轮把周会整理接入独立、无工具权限的中台 Agent，继续使用公司的模型选择、额度和执行预算。模型只返回候选原文行号与任务内容；人员映射、日期解释、字段校验、人工确认与派发均由后端完成。中台不可用或返回不合格时可回退原模型，再失败时保留规则预拆；日志显示实际请求来源，草稿不冒充中台成功。

真实中台探针发现，给每条候选同时发送原文、重复内容和整份会议文本会触发中台插件层的内部 JSON 解析错误。输入改为每条完整事项仅传一次，仍保留全部候选和原文行号，后端保存原文与分组供日期、人员映射和人工核对。这不是截断内容或接受不完整输出。

## 接口和数据边界

- 新增 `POST /api/v1/task-imports/{batch_id}/reparse`，请求 `{ "version_no": 1 }`。成功返回更新后的批次详情，不创建任务。
- 只允许原创建人重新整理未派发、未人工编辑的草稿。页面有未保存变化时先拒绝；后端在模型调用前后各检查一次身份与版本，成功后才使用 V194 窄函数保存。推理期间不持有数据库锁，冲突或失败保留原稿。
- 数据库再次强制原文、哈希、会议日期与创建人不可变；所有人工选择均阻止覆盖。普通保存和正式确认的既有规则保持。
- 同一天的多种日期表述先归一，例如 9 月 27 日会议的“明日（9.28）”。日期、时点或早晚冲突仍需人工确认；Q3 和 OKR 里程碑不猜截止日。只给日期时保留暂用北京时间 23:59 的提示。
- `source_warnings` 仅为草稿展示字段，不进入保存或派发命令。旧草稿不会自动更改日期；人工补齐后不再显示过时缺项提示。

## 日志与权限

业务名称补齐周会整理、资料导入、接口测试及各语音入口。未知编码保留原编码，便于定位新增业务；实际模型/Agent 名、调用来源和错误码分开显示，不把所有错误写成模型输出格式问题。

V193 新增 `security.finish_inference_operation`，只允许原公司、用户、角色将自己的 running 回执一次性转入终态。API 仍没有读取私有回执的表权限，API/Worker 的直接 UPDATE 被撤销。收尾不重新授权业务动作，因此中途暂停租户或撤销权限后仍能记录取消/失败。历史默认函数权限一并收敛，PUBLIC、飞书和观察角色不能借此修改记录。

V193/V194 首次迁移仅执行各自新增的窄授权与撤销，不重新运行历史完整授权链。隔离升级发现旧链会给已按安装策略收紧的 API/Worker 加回 42 项权限；生产只读核对确认这些权限当前均未授予。维护用的兼容授权函数保留，新功能授权同时排除 PostgreSQL 的 `pg_` 内建角色。原位升级必须验证既有权限保持不变，不能以扩大权限或事后忽略差异通过检查。

已有历史 running 回执没有被批量伪造为成功或失败；本轮只修复后续正常收尾。生产需分别核对新请求和旧事件的事实证据。
