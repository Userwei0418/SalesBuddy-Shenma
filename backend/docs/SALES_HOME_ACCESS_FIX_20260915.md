# 总览快捷入口与销售本人业务权限修复

用户明确：一线销售、销售总监、销售总经理均保留「客户认领 → 记录客户拜访 → 创建任务」；FDE、FDE负责人保留「记录客户拜访 → 创建任务」。三类销售可以为本人申请客户、记录和补充本人拜访。FDE 的即时录入开关及本人商机名单校验继续有效，未开启能力时不能仅因 UI 展示而获得权限。

## 实施边界

- 三销售角色 `customer.claim`、`visit.create`、`visit.supplement`、`task.create` 统一开放。经理开放 `VISIT_ENTRY` 分析模式，结构化和独立质检仍不直接归档，正式记录由本人确认。
- `/assistant/home` 的 `quick_actions` 按实时能力返回同样的顺序和语义；移除这里原有创建新客户等不一致的旧入口。客户建档仍只由运营后台完成。
- V094 扩展认领申请与审批复核的有效身份；申请仍为 pending，必须由运营审批。保留锁客户、唯一归属、并发竞争申请关闭、驳回原因、释放版本校验、通知及审计。
- 申请时检查有效业务角色、工作区及启用账号；审批时重新检查申请人账号和角色，已停用或撤销角色不能通过。
- 认领不修改客户原来的 `owner_team_id`。总经理没有团队编号也可申请，不新增或猜测团队；本人拜访继续采用现有客户团队作为无个人团队时的记录团队。
- 主管认领原属其他团队的客户并获批后，通过当前本人归属读取本人客户。该分支只认当前已审批 ownership，原团队、历史参与访问分支保留；认领客户不开放他人的独立商机权限。
- 补充服务继续要求 `recorder_user_ref_id == actor.user_id`。能看团队记录不等于能代他人补充。经理仍不被纳入销售画像打分对象。
- FDE 不开放认领、建档、商业字段编辑。FDE 的拜访资格、归档身份、退出商机后撤权以及任务权限保持现有规则。

## 前端验收纠正

- FDE负责人作战地图和商机列表移除团队／个人切换及地图冗余权限说明。默认完整授权团队，通过列表人员筛选收窄；普通FDE仍为本人。看板和“我的”的团队／个人切换保留。
- 旧个人scope不再意外缩窄主Tab；看板的本人钻取转换成选中本人，指定成员钻取保持。同角色换账号清理旧选人。
- 三入口凹口布局仅用于完整三项；一／二项用紧凑布局。FDE原有两按钮外观保留，避免缺少入口时语音偏左或裁切。
- 旧权限恢复时，认领、录入、确认页重新初始化并保留原客户／商机／visitId。补充入口以服务端recorder_id与当前用户匹配；同名他人不能补充，本人改名不受影响。
