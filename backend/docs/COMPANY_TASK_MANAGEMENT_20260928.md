# 公司后台任务管理改版（2026-09-28）

## 需求与范围

将公司后台的“我的待办”改为“任务管理”。管理员默认查看权限范围内的全部任务，并按负责人、状态、日期和周任务批次筛选；提供列表和按人的周/月时间线。保留个人相关任务快捷筛选，突出“发放周任务”和“批次与进度”。

沿用现有 `task.read` 授权与行级权限，不因进入后台而增加数据范围。小程序个人待办、任务接收/验收/转交/取消流程不变。只有管理员从后台正式确认周任务批次时，才沿用既有大群通知；查看、筛选、草稿保存及成员直接派发不产生新群通知。

时间线展示“创建或批次正式派发 → 截止日期”的排期区间，不代表实际开工时间、工时或完成百分比。未领取岗位任务和历史停用负责人明确展示。转交后以当前负责人归组；兼容历史多负责人任务，在各负责人行展示，但任务总数去重。当前正式任务的数据库截止字段不允许为空；前端仍防御性处理缺失字段，草稿缺日期不会混入正式任务。

## 查询契约

- `GET /api/v1/tasks/management`：有界分页、全筛选结果统计和用于时间线的排期字段。
- `GET /api/v1/tasks/management/owners`：同一授权范围内可见任务的当前/历史负责人目录；不要求创建任务权限。
- `scope=all|mine`：全部当前授权范围，或本人发起/负责/候选的任务。
- 状态、逾期、负责人/未领取、批次、北京时间起止日及无截止日期筛选均由服务端处理。
- 日期窗口按排期区间相交筛选，起止日按北京时间计算。无截止日期任务显式保留或排除。
- 汇总按整个筛选结果计算，不以当前页推算。未完成统计包含待验收，已取消单列。
- 周任务元数据复用受控批次摘要，不向非创建者暴露草稿原文。
- 时间线按当前页显示并明示当前页数量与全筛选数量，保留分页，不一次拉取全公司所有任务。
