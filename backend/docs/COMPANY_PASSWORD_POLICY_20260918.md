# 公司首次改密策略

系统管理员在「账号与组织 → 登录与密码」开启或关闭当前公司的首次改密要求。运营可查看，业务角色无权访问。新公司未配置时默认开启。

关闭后，小程序与 Web 的初始、重置密码均可直接登录；开启后，仍使用初始或重置密码的账号需要改密，已经自行修改过密码的账号不受影响。策略保留原始凭证标记，由登录、刷新会话及每次受保护请求共同执行。开关不会修改密码或撤销会话；单独重置密码会撤销该账号现有会话。

接口为 `GET/PUT /api/v1/console/password-policy`。写入要求系统管理员、当前公司授权、版本号和幂等键；审计记录不包含密码。数据库 V102 增量引入私有策略表与受控函数；V101 与已上线的历史迁移保持一致。

授权批量维护使用 `backend/scripts/reset_company_passwords.py`：显式列出公司，以已有管理员身份先预览账号数量和计划摘要，再以摘要执行。密码仅从标准输入读取，整批在一个事务中独立加盐、核验并撤销会话，不为平台授权身份创建密码，不改客户业务数据。账号、版本或策略变化会使旧计划失效；失败不输出数据库诊断或凭证。

验证：30 项 PostgreSQL 集成测试通过，覆盖实际小程序/Web 登录、刷新、开关即时生效、公司隔离、权限、版本冲突、幂等及批量重置；40 项密码、认证配置与分层检查通过。
