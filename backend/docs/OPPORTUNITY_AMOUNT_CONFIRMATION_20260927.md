# 商机金额核对与单位一致性

## 业务规则

本轮用户确认：保留万元输入方式，**商机 ACV 达到 1,000 万元时（包含等于）提醒**，明确确认后仍可保存。各公司可在后台“公司规则配置 → 商机大额确认提醒”调整阈值，按既有草稿、预览、发布、历史恢复流程生效。阈值字段 `warning_threshold_wan` 是正整数万元，不是允许保存的金额上限。

- 输入旁保留明确单位，并实时显示实际元金额与万元/亿元量级。
- 新建或实际更改 ACV 时读取当前公司规则；达到阈值才需要大额确认。
- 编辑其他字段且 ACV 不变时，不重复提醒。历史大额金额不自动缩小或改写。
- 小程序独立商机在保存前确认；拜访在最后“确认归档”弹窗中一起确认，质检阶段不重复弹窗。
- 取消确认、规则读取失败、表单或身份已变化时，不提交本次保存，保留可继续编辑的表单。
- 本轮大额策略只覆盖商机 ACV；季度确收、回款预测沿用既有规则。

## 单位与接口

数据库、API `amount`、AI 商机候选标准字段 `amount` 及飞书 Base 金额字段均使用**元**；小程序与后台录入框使用**万元**。手工输入只进行一次乘 10,000，回填按元除 10,000。AI 候选不再根据数值大小猜单位：标准 `amount=1200` 指 1,200 元，不能预填为 1,200 万元。显式 `amount_wan` 或带单位的输入仍按明确单位解析。

万元 ACV 输入最多六位小数，精确到分。历史 `12345.67 元` 回填为 `1.234567 万元`，仅编辑名称时保留原金额，不因旧四位小数限制而无法保存，也不截断角分。控制台用十进制整数分转换；小程序在构造精确十进制值后核对 Number 可表示性，无法精确往返时提示修改，不静默舍入。

新增请求字段 `amount_confirmed_value`（元、可空、与 amount 相同精度）表示用户本次实际确认的金额。达到阈值时必须与最终 `amount` 相等；不是可复用的布尔开关，不从 AI、旧草稿或旧确认中自动复制。金额改动后必须重新确认。该字段不改变金额本身、不作为商机业务字段落库。

策略读取：

- 小程序：`GET /api/v1/company-rules/presentation` 中的 `opportunity_amount`。
- 运营后台：`GET /api/v1/console/opportunities/amount-policy`，商机创建或编辑任一权限可读，不额外要求公司规则管理权限。
- 两者返回当前公司策略快照，定义为 `{"schema_version":1,"warning_threshold_wan":1000}`。

`services/opportunities.save_opportunity` 是手工商机、后台商机与拜访归档的共同保存入口，写入前独立校验当前阈值和确认金额。未确认时返回明确的业务错误，不写商机、不生成成功回执或下游通知。拜访消费已质检记录前也预检；确认字段不参与质检业务快照比较，但金额、客户、商机等原有业务字段继续严格比较，因此不会因增加确认动作迫使用户重跑质检。

幂等摘要只在上述商机保存顶层与拜访归档 `fields._opportunity_mutation` 中排除 `amount_confirmed_value`。确认值仍完整送入实际写入校验；真实金额、客户、版本和质检批次等继续参与摘要。已成功提交但客户端未收到响应时，即使公司调整阈值导致重试增减确认值，仍返回同一回执，不重复创建；改变真实金额等业务字段仍返回冲突。其他业务操作及其他位置的同名字段不被忽略。

## 通知显示

新生成的飞书商机通知显示完整千分位金额、单位和中文量级，例如 `1,000,000,000元（10亿元）`；阶段使用现有中文名称。外币保留其币种，不标为人民币。未知或非法值明确显示未填写/格式异常，不伪装成零。Base 数值仍是元，冻结的待发送通知沿用原内容，已发通知不补发。

## 配套发布

数据库增量为 `V187__opportunity_amount_confirmation_policy.sql`：在既有规则白名单新增 `opportunity_amount`，补全局默认策略，不迁移或修正任何客户商机金额。已有规则的权限与发布机制保持不变。

后端、V187 与新前端配套验收后再发布。**旧小程序没有金额确认字段**：低于阈值的保存及金额未变的编辑继续兼容；新建或修改为达到阈值的大额会被新后端以 422 拒绝，须更新小程序后确认保存。不能只上后端后将旧版大额保存失败误判为系统内部错误，也不能为兼容旧版跳过金额检查。

本轮不自动更改截图中的生产商机金额，不读取群聊，不发送飞书消息。真实金额需由业务负责人核实后按正常编辑流程修正。

## 验证入口

- 后端单测：`tests/test_opportunity_amount_policy.py`、`tests/test_opportunity_amount_console.py`、`tests/test_feishu_cards.py`。
- PostgreSQL 真实 HTTP/事务回归：`tests/integration/test_opportunity_amount_confirmation.py`，涵盖三个保存入口、精确边界、公司策略隔离、取消/未确认无写入、重试及旧质检快照兼容。
- 前端行为回归：公司阈值、取消/晚到请求、草稿旧确认清除、实际拜访页 AI 元金额预填及提交。
- 本地配套环境须重新 `up`、`verify`、`check`；单测或接口夹具通过不等于微信真机或真实 AI 联调已验收。
