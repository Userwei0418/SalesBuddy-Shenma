# 管理后台 AI 连通性测试

2026-09-16：在模型接口配置的每个用途卡片、智能体运行配置的每个绑定卡片增加「测试连通性」。仅系统管理员可操作，沿用当前公司的已生效配置与服务端凭据，不要求重新输入密钥。

## 行为与边界

- 直连接口：文字使用固定短问题，转写使用内置测试音频，语音合成为预留用途，缺少音色时明确提示未执行。
- 智能体：经现有后台任务队列执行，复用正式智能体任务进程的配置和凭据；先验证中台连接与鉴权，再用空业务资料的固定样本请求推理。接口进程可能仅有绑定元数据，不能用其凭据加载状态冒充任务进程实际状态。不读取真实客户事实、不下发业务工具凭证、不进入业务写入或原接口兜底。
- 回执显示测试对象、连接与鉴权、固定样本返回、耗时、测试时间、配置版本、模型或智能体编号；中台有返回任务编号时一并展示。
- 智能体返回完整 JSON 只代表该固定样本有响应，不代表业务字段、语义或所有业务场景验收通过。实际执行快照无可信回执时保持未核验，不能用预期绑定版本冒充。
- 停用、缺凭据、绑定不一致均显示「暂不可测试」，不会擅自切换服务商。编辑窗口原有测试仍用于待发布配置验证，与此入口分开。
- 测试可能产生少量服务商调用费用。每公司每分钟最多发起五次；相同测试编号重试返回已有回执，不重复发起调用。测试超过九十秒仍没有完成回执时提示结果未知，允许显式重新测试。
- 复用现有技术审计表保存起止回执，模型调用记录标注「接口连通性测试」。智能体测试任务仅执行一次，执行前重新核对管理员身份，排队过期、撤权或已有发出标记时不发起调用；完成回执与任务完成凭据一同提交，任务租约仍受现有保护。不新增数据库结构，不修改绑定、业务记录或发布记录，不允许用连通性回执发布配置。
- 密钥不返回浏览器或进入测试回执；错误只展示中文分类及可用的状态码。接口仅接受服务端已登记的用途/能力与 UUID，不接受任意 URL、凭据或真实业务内容。

## 接口

- `POST /api/v1/admin/ai-connectivity/{kind}/{target}/tests`，请求仅 `request_id`。`kind` 为 `direct` 或 `agent`，`target` 是现有用途或业务能力编号。
- `GET /api/v1/admin/ai-connectivity/tests/{request_id}`，仅当前公司、当前管理员可读取自己的回执。
- 智能体提交先返回排队回执，页面自动查询完成结果；客户端断连时可使用同一编号查询，完成后点「重新测试」会产生新编号。

## 验证

- 新增单元测试覆盖重复请求、限流、异常脱敏、超时、中台鉴权失败、缺少必填中台输入、JSON 返回失败、停用用途及继承配置。
- 真实隔离 PostgreSQL 测试覆盖正式密码登录、管理员权限、回执查询、重复请求、额外字段拒绝、限流及配置发布记录不变。
- 浏览器使用隔离数据库验证两个页面入口与中文回执；生产固定样本验证另行记录，隔离测试不作为供应商真实可用性的证明。
- 小程序代码未改动，无需因此上传或提审小程序。

最终本地结果：后端非数据库测试 1,645 项通过；隔离 PostgreSQL 集成测试 471 项通过、1 项可选大数据测试跳过；现有前端回归 616 项通过；数据库静态检查 5 项通过；OpenAPI 与代码一致。新增真实数据库队列测试验证只入队一次、Worker 实际领取、完成凭据与回执、页面查询及再次请求不重复执行。浏览器核验直连和智能体按钮、缺少密钥/绑定的中文提示及弹窗布局完成。此轮没有新增数据库迁移。

生产验证使用 `backend/scripts/verify_ai_connectivity.py` 显式指定用途或能力。脚本通过正式维护管理员身份提交同一服务，智能体自动等待实际 Worker 回执，并验证查询/重复提交和配置未变。部署时应同时升级 API 与 Worker；页面可用不等于每个供应商或业务场景已通过。
