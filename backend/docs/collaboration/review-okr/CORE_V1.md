# Review 核心后端契约 V1

本切片从 M1 `5dfa3dccff414082b142621d37f6beccc636ccc7` 选源，组合概览、O/KR、任务关系和 V241–V243。对应原 Web 核心候选 `554ab087eb7c41dbf51c9084bdf1fc0402e0120f`。这是 2026-10-14 晚间四项新要求之前的可追溯基线，不表示已上线或业务验收；DELTA04 的多选范围、具体目标对象与“其他原因”、商机全字段变更由新后继交付，不应从此版本推断支持。

## 概览和明细

- `GET /api/v1/review/overview`、`/activities`、`/opportunities` 共用 `scope=self|member|team`、`member_id` / `team_id`、`anchor_date`、`period_type`。当前只接受单成员或单团队；请求的选择范围和服务端授权范围分开返回。
- 一个只读 repeatable-read 事务内取得授权事实、周期、时间和统计。明细按业务 ID 去重后分页，金额使用十进制字符串。不能将可见小计当作完整团队业绩；无权限、来源不足、无目标和明确的零分别表示。
- 保留 `forecast_collection`、`collection_ppl`、`forecast_recognized` 三种计算能力。预测回款以高回款信心的季度预测为分子、`collection` 生效目标为分母；PPL 概率至少 30、使用独立 `collection_ppl` 目标；确收预测概率至少 70、使用独立含税 `forecast_recognized` 目标。只使用生效目标，不使用待审值。后继界面顶部仅显示前两种，不改变现有指标身份。
- 七类动作：新认领客户、正式跟进、新商机、丢单商机、变动商机、已完成任务、待处理任务。商机池五种筛选及各指标商机下钻共用授权事实。旧历史不能证明的字段、日期、归属与昨日基线保持缺失状态。

## O/KR

- `/api/v1/review/objectives` 与 `/key-results` 提供列表、单条、创建、按版本更新；进展通过 `POST /key-results/{id}/progress`，提醒沿原受控通知入口。
- UUID 标识与 `version_no` 乐观锁。负责人唯一，协作者去重；上级必须同租户、可见、周期兼容且无循环。
- KR 通过 `metric_code` 和可选 `target_id` 引用生效目标，不复制或改写目标金额。非财务手工进展必须明确确认并附证据。上下级对齐不自动分摊或汇总金额。
- 归档 O/KR 及历史仍可读；新确认、新上级连接必须同时满足 KR 和所属 O 活跃。合法原幂等回执可重放但不新增进展或历史；权限撤销后不可返回旧受限回执。
- 数量指标采用明确当前归属与可追溯创建/正式跟进证据。缺日期、归属不明、源范围不足时返回已知小计和缺失原因，不伪造完整零值。

## 任务关系

参见 `TASK_ALIGNMENT_V1.md`。旧请求可以省略 `alignment`，不自动补关系；新增字段缺省不改变旧幂等请求摘要。当前 V1 是 `metric_codes`、`key_result_ids` 和可选计划贡献，`PATCH /api/v1/tasks/{id}/alignment` 以当前任务版本替换关系。贡献只是声明，不自动计财务业绩。新 Web 必选具体周期目标/KR或其他原因属于 DELTA04 后继，本版的类别输入不构成该要求的完成证据。

## 数据库与权限

- V241 新建 O/KR 与受控函数、行权限；V242 新建任务关系；V243 更新数量指标口径。
- API 只获必要读权限和受控写函数；不授予新业务表直接写入。Worker、飞书、平台角色不因本切片获得报告取材权限。
- 发布契约冻结 V240–V243 各阶段完整迁移、权限、RLS 指纹和实际生产历史注册前缀；未知后继迁移不能被旧计划顺带执行。
- 不包含 V244/V245、日报周报生成器 `dda4388`、报告冻结/Worker 新授权，也不包含新用户要求的 V246+。M1 线上源、目标字典、审批、小程序接口保持原固定字节。
