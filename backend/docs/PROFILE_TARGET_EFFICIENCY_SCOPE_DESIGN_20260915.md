## 3. 季度目标与审批

### 3.1 目标对象与来源

目标唯一身份是“业务组织/人员 + 季度 + 指标”。对象绑定稳定 ID，名称仅展示。部门、团队使用现有已确认的组织映射，不按中文名称匹配，不以全部工作区账号充当销售部门。

- 运营可配置部门、团队、个人季度目标，记录来源、操作者和时间。
- 本人可录入自己的目标；查看团队、部门或其他成员均为只读。
- 两种来源操作同一份生效目标。运营先录过，本人再改属于变更；不能按“本人第一次点保存”绕过审核。
- 上级目标独立保存。比如部门目标 1000 万、各团队合计 800 万，保留各自原值；不自动补齐，也不因新增人员变为 1200 万。可显示分配差额供运营核对，但不阻断保存、不自动摊派。
- 多团队联合查看可以合计所选团队已生效目标；这只是查询结果，不写成新的部门目标。任一团队缺目标时说明缺失，不把已知部分当作完整目标。
- 年度历史保留；不将年度除以四填入季度，也不由季度反写年度。

### 3.2 表单建议

一个季度使用一张表单，替换两个临时单输入弹窗：

| 字段 | 行为 |
| --- | --- |
| 查看对象 | 本人入口只读；运营入口选择部门/团队/个人 |
| 目标季度 | 默认当前季度；个人建议只设置当前季度，历史查看只读；运营可维护指定季度并留痕 |
| 回款目标 | 录入目标金额，显示当前生效值与拟提交值 |
| 确收目标 | 同上，与回款分别保存和计算 |
| 设置/调整原因 | 按用户本轮要求必填；记录商定依据或变更原因 |
| 申请状态 | 展示待审批、通过、驳回及意见，不能覆盖为普通“保存成功” |

金额沿用现有正数、最多两位小数校验，页面标清“万元”，入库统一人民币元。0 目标目前不支持，本轮不擅自放开。未设置与 0 不互换。其他已有指标继续在通用后台保留，本轮“我的”主要接回款和确收，不增加新的销售考核项。

### 3.3 首次、变更与待审

建议以一次表单提交为一张申请，保证反馈清楚：

1. 目标都未设置时，本人首次提交直接生效，记录原因及来源，随即锁定为生效版本。
2. 已有目标不变、只补尚未设置的指标，按该指标首次录入处理；提交结果列明哪些新增、哪些未变。
3. 只要本次提交修改任何已有生效指标，整次提交进入一张变更申请。包括同时补填的新指标，也随整单审核生效，避免“一半通过、一半待审”。
4. 待审时展示“当前生效值”和“申请值”；完成率继续使用当前生效值。通过后整单生效，驳回保留原值和原因。
5. 同一对象/季度已有重叠待审项时，不静默覆盖申请。展示现有申请；重复提交同一内容返回已有结果。
6. 运营直接调整已生效目标时记录调整原因。如果和待审申请冲突，明确告知并关闭该整张旧申请，保留历史，不让旧审核覆盖新目标。
7. 已有值提交必须携带版本；新建必须确认仍未设置。审批核对各指标基准版本、申请状态和对象有效性，在同一事务中生效。
8. 跨季度完成的审批仍属于申请中原季度，不自动转到新季度。个人季度限制与后台历史维护要由服务端校验。

“锁定”表示后续改数走受控流程，不妨碍正式实绩持续增长。现有 V084 的锁、版本和审计机制可复用；多指标申请需新增数据库迁移，不能修改已应用迁移。

### 3.4 完成率与其他卡片

`当季度完成率 = 当季度已登记且未作废的回款/确收 ÷ 当季度已生效的对应目标 × 100%`

- 按实绩发生日、北京时间归季度；例如 Q2 签单、Q3 回款，计入 Q3 回款。
- 缺目标显示“未设置”；无登记显示“未登记”；目标待审不影响已生效版本的计算。不得用预测回款、预测确收、ACV 或赢单额代替正式实绩。
- 完成率文字可以超过 100%，进度条最多铺满，评分继续依现有权重及封顶规则。
- 团队/部门金额是该范围去重汇总，目标是该对象独立目标；不能以成员目标平均或累计替代。
- 在推 ACV、赢单金额保持各自存量/累计口径并标注；客户保有率仍用现有同期年度收入定义，不因目标转季度就悄然改公式。

## 4. 营销效率

### 4.1 三个维度

| 维度 | 指标及显示建议 | 口径 |
| --- | --- | --- |
| 客户 | 高潜客户占比，例如“60% · 第一、二象限 12 / 20 家” | 主攻区 `main_attack` + 客户资产 `customer_asset` / 范围内全部客户 |
| 商机 | A+B 商机占比，例如“40% · A、B 级 4 / 10 个” | A+B / 范围内总商机；沿用在推及赢单、排除丢单和删除记录 |
| 跟进记录 | 保留次数、记录和评分信息 | 统计已确认/归档记录；质量得分仍取有效评分平均值，次数不替代质量分 |

等级依据：`frontend/miniprogram/utils/quadrant.js` 明确一、二象限枚举；象限沿用已保存评价及规则版本，不在效率页再写死 70 分。商机沿用现有正式分档：A ≥100 万，B ≥50 万且 <100 万；后端 `repositories/opportunity_browse.py` 与前端 `utils/opportunity.js` 一致。

### 4.2 人数、去重、时间和缺失

建议默认以“当前总量”衡量客户/商机结构；如保留“本年新增”辅助筛选，分子和分母必须使用同一批本年创建记录，明确按其当前象限/等级计算，不伪装成历史快照。客户、商机共用结构窗口；跟进质量使用独立的周/季/年窗口并显示起止时间。总分携带这两组窗口，切结构窗口只更新客户/商机输入，切跟进窗口只更新跟进输入，分项卡及总分解释对应一致。季度目标选择只影响成熟度的目标及实绩。

- 个人使用所选人的客户、商机和本人录入的跟进；主管查看成员不能混入主管本人的评价或数据。
- 团队/部门先按客户 ID、商机 ID、跟进 ID 去重，再算分子/分母，不能平均个人百分比。两人分别 1/2 和 8/8、对象无重叠时，团队应为 9/10=90%，不是 75%。
- 客户集合与对应主体的作战地图一致；同一客户在团队只计一次。个人读该人员有效评价。团队/部门的单一评价来源当前尚未按所选主体统一；建议只从所选范围成员及负责人的有效评价中，按评价时间、记录 ID 降序取一客一条，没有该范围的评价则待评估。这是本设计提出的统一规则，不是现成的团队评价接口。
- 当前地图在领导视角取可见最新评价，画像在团队范围按“客户+评价人”取多条；这是需要统一的实现差异。需抽取共用主体聚合，固定客户范围、评价来源和稳定排序，使地图穿透列表与效率统计一致。不能直接将领导可见的任意最新评价代称为所选人员结果，也不能任意挑高分或合并多个人的分数。
- 无客户/无商机时分母为 0，显示“暂无数据”，不计算为 0% 或 100%。
- 有客户但部分待评估：总客户仍是分母，已确认高潜是分子，另列“待评估 N 家”和覆盖率；全部未评估时显示“待评估”并不参与总分。未知商机金额同理不能冒充已确定 C/D 级。
- 所有统计在服务端对授权完整集合计算；前端不能用当前分页或排行榜行数充当总体。

### 4.3 总分与解释

建议沿用后台当前生效的营销效率权重，默认跟进 40%、客户 30%、商机 30%。客户维度从“客户评分平均分”改为“第一、二象限占比”；商机用 AB 占比；跟进用原有效记录平均分。缺失维度沿用已有按有效权重归一的逻辑，并显示覆盖情况。

这是明确公式计算，不新调用 Agent 决定百分比。评分名称、规则版本、说明和响应来源须同步更新；历史评分保留原口径，不能拿旧版本做伪同比。数量榜如保留，需与质量占比清楚区分，不在“客户占比”下仍按客户数排榜。最小方案以占比卡为主，保留跟进记录，不另增加一组跨团队排行榜。

团队/部门入口保留；金额及数量写“汇总”，效率写“占比”，六维画像可写“平均”。避免一个“部门平均”标签让所有数字被理解成简单平均。

## 5. 查看范围、穿透和编辑权限

| 登录身份 | 可选查看对象 | 目标可写范围 | 查看其他对象 |
| --- | --- | --- | --- |
| 一线销售 | 本人 | 本人首次填写/变更申请 | 不开放其他成员画像 |
| 销售主管 | 本人、所辖成员、所辖团队 | 仅本人 | 团队和成员只读 |
| 销售总经理 | 本人、授权部门成员、授权团队、部门汇总 | 仅本人 | 团队/部门目标和他人目标只读 |
| FDE | 本人 | 本人 | 使用 FDE 专属项目及协作范围 |
| FDE 负责人 | 本人、所辖 FDE 成员、所辖团队 | 仅本人 | 成员和团队只读，保留 FDE 指标 |
| 运营/管理员后台 | 职责授权下的目标对象 | 配置目标、审核变更 | 后台操作留痕；不依赖小程序选中对象授予权限 |

具体交互和后端约束：

1. 复用看板已验收的紧凑范围控件和底部选人风格。“个人”始终指向一个人；团队筛选收窄人选，切团队后无效选择清除，不回退到全员。
2. 三个页签共用当前查看主体。选中 A 后，经营事实、效率、画像都属于 A；切换时清除旧数据，旧请求不能回填。销售六维画像保持现有适用岗位：销售、主管。总经理选本人时，画像展示“该岗位暂不适用”，仍可查看本人的目标和经营事实，不新增经理画像或复盘权限。
3. 范围目录由后端返回有效用户/组织 ID。金额、目标、效率、画像各接口都重新校验身份和所选对象，不以姓名/账号文本或前端过滤作为权限依据。
4. 主管按所辖业务团队穿透，总经理按授权部门穿透。不能把整个工作区的运营、其他部门人员混入“部门成员”。现有“北区＋东区 / 南区＋港澳”授权分组沿用，不在此处重新定义组织。
5. 成员详情、跟进、客户、商机跳转需同时满足查看主体和实际记录权限。看到汇总或公共榜名次，不会自动获得客户详情/原文权限；不得伪装登录为所选人员，也不得授予修改他人数据的能力。
6. 所选人/团队没有数据就显示空状态；不拿本人结果、演示数据或其他范围结果填空。接口错误与无数据分开提示。
7. 非本人视角不展示“编辑目标”“发起本人画像复盘”之类写操作；后端仍独立拦截。打开本人表单后切账号/主体/季度，旧表单不能提交。
8. 会议提及主管参考公司平均；本轮不以此开放其他团队详情。若保留对比，仅通过既有授权的汇总基准展示，不扩展成员目录或 CRM 权限。

FDE 的“项目成果/协作效率/FDE 画像”继续独立：本次不能把销售的客户质量占比直接替换 FDE 的协作完成数、跟进和项目指标。季度目标、本人可写、选人、空态及样式可以共用；FDE 协助项目金额保持项目整体口径，团队按项目/实绩去重，本人跟进仍按录入者，团队历史按既有录入时团队快照归属。六维画像及 Agent 职责均保持。

## 6. 建议实施与验收顺序

本轮只交付设计。后续按三项交付，以当前契约为基线小步修改：

1. **季度目标**：通用目标读写/表单/审批原因/运营入口/销售与 FDE 当季实绩贯通。涉及数据库只新增迁移，同步接口和测试；独立验收首次、变更、审批前后及越权场景。
2. **营销效率**：抽取完整主体聚合，替换客户公式、统一商机分档、更新卡片与分数解释及版本。验收分子分母、去重、空值、时间范围和 40/30/30 生效权重。
3. **穿透与 UI**：统一选人/组织 ID、只读/可写标志、三页签主体及异步隔离；销售、主管、总经理、FDE、FDE 负责人逐身份验收。

关键验收示例：

- 本人首次设置 100 万直接生效；运营先设置 100 万后本人申请 80 万，审批前仍按 100 万计算；驳回不变，通过后 80 万。
