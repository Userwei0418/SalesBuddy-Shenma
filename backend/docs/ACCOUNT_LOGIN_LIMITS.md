# 账号登录限制管理

账号登录窗口仍为 15 分钟 5 次，网络 IP 窗口仍为 15 分钟 50 次。计数是登录尝试数；账号成功登录后清除自己的账号窗口，网络窗口保留。密码强度、首次改密与会话撤销规则保持现有行为。

`GET /api/v1/console/organization` 的每个账号增加：

- `login_locked`：下一次账号登录是否受到账号窗口限制，不代表 IP 状态。
- `login_retry_at`：账号窗口结束时间，未受限时为 `null`。
- `login_attempts`：当前有效窗口内的尝试数，窗口过期返回 `0`。

`POST /api/v1/console/accounts/{user_id}/unlock-login` 接收 `{version_no, reason}`，原因去除首尾空白后为 1–500 字。客户端沿用管理写操作的 `Idempotency-Key`，响应为 `{id, version_no, login_locked, login_retry_at, login_attempts}`。处理在同一事务内核对账号版本、解除指定账号限制、记录原因并递增账号版本；同键重试回放原结果，新键提交旧版本返回 409。不存在的账号返回 404，权限不足返回 403。

运营可以管理普通业务账号；运营及系统管理员账号由系统管理员管理。数据库函数同样校验当前有效角色及工作空间，只接受目标用户 ID 并在内部派生账号限流键，调用方不能传入 IP 或其他工作空间限流键。

既有 `reset-password` 成功时也清除目标账号窗口，并增加上述三个状态字段。原有强制首次改密、重置后撤销旧会话行为保留。解锁自身不会修改密码、会话、角色或部门。

账号解锁不清除网络限制。小程序和 Web 登录遇到限流时均返回 429，`detail` 区分“该账号尝试较多”“当前网络尝试较多”及同时受限；`Retry-After` 为实际剩余秒数，同时受限取较长窗口。后台表述统一为“解除账号限制”，不能承诺解除 IP 保护。

V073 在 `security.login_throttle` 原状态上增加三个窄函数，没有新表：`login_limit_status`、`account_login_status`、`unlock_account_login`。限流表仍不授予运行时角色读写权限；预登录状态函数显式允许执行，管理函数在内部校验身份。迁移先于新后端发布。

每次解锁在同事务写入 `ops.audit_log`：动作 `account.login_unlock`、对象类型 `user_ref`，仅保存目标、操作人、原因及解除前后限制状态，不记录限流键或凭据。“业务操作记录”沿现有 `account.change` 分类展示“解除账号登录限制”；密码重置与解除同组时显示“重置账号密码”。可按账号、操作人、原因查询；技术审计可按精确动作查询。

验证覆盖：普通服务/展示回归、真实 HTTP + PostgreSQL 限流/解锁/重置/幂等/权限/审计、生产权限形状下既有及后建运行时角色的窄函数权限和私有表拒绝访问。隔离技术测试不代替部署后的真实账号验收。
