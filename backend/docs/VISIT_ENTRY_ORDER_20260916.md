# 跟进记录按系统录入时间排序

2026-09-16。仅后端接口与 V100 查询索引；小程序适配由另一任务独立交付。

`GET /api/v1/visits` 新增可选 `sort=created_desc`，客户跟进与单个商机跟进均支持。显式选择后返回顶层 `sort: "created_desc"` 回执，并按真实 `created_at DESC, id DESC` 排序。每条记录返回含时区的实际 `created_at`。

不传 `sort` 保持原拜访日期排序，也不增加排序回执，便于新客户端识别旧服务器。`created_date` 仍为人工填写日期优先的展示字段，`visit_date` 仍取拜访发生时间；不能用这两者代替系统录入时间排序。未改动既有记录日期。

游标绑定排序模式、客户和商机。混用不同模式、主体或游标与非零 offset 返回 422；同一录入时间以 UUID 稳定排序；中途插入更晚记录不会挤乱下一页。列表主体授权和行权限继续使用现有规则，不扩大销售或 FDE 的范围。

V100 为未删除记录增加客户/商机两条录入时间索引，未改变业务数据和权限。

验证：10 项相关单元/契约测试、469 项真实 PostgreSQL 集成测试通过，1 项既有万条容量观察跳过；OpenAPI 与源码一致，静态检查通过。新增覆盖归档时间不可改前提下的日期矛盾样本、时间并列、分页插入、销售/FDE 身份和接口回执兼容。生产回执另见部署证据。
