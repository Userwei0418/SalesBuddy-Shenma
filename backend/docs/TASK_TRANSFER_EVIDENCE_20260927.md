# 任务转交证据补充（2026-09-27）

状态：本地候选，未部署。此次保持既有人工转交流程：用户确认转交给谁，谁就是负责人。

## 变化

- `POST /tasks/{id}/events` 的 `reassign` 事件保存操作时姓名：`payload.actor_name`、`payload.previous_owners[].name`；原来的用户 ID、岗位、团队字段及 `new_owner.display_name` 保留。
- 转交通知复用相同证据，标题为“某人将任务转交给某人”，正文保持任务标题。通知接收者仍为原负责人、新负责人、发起人的去重集合，排除操作者。
- 取消事件共用协调写入流程，也保留这些姓名快照；取消通知标题、状态和流程不变。
- 同人转交仍拒绝，提示“当前负责人就是此人，无需重复转交；如需转交，请选择其他有效接收人”。不新增恢复、领取或二次接受等业务规则。
- 历史事件不回填姓名，不推测任务最初意图；以后账号改名不改变已保存的转交证据。

## 不变的边界

权限、任务可见范围、状态机、版本检查、转交事务和幂等机制保持原实现。姓名仅用于展示，接收人和授权仍按稳定 ID 处理。此变更不包含负责人动态资格规则，不自动修复或改派生产任务。

## 验证

新增 `tests/integration/test_task_transfer_evidence.py`，在一次性 PostgreSQL 中以受限应用角色执行：

1. 转交后状态仍为待接受，版本递增一次，发起人保留，新负责人就是人工指定者。
2. 转交事件、技术审计、通知均含同一份操作者／原负责人／新负责人证据；账号后来改名不改历史。
3. 三组发起人、旧负责人、操作者重合情况，通知去重且不通知操作者。
4. 旧版本再次转交被拒绝，无负责人、历史或通知变动。
5. 转交给当前负责人被拒绝，无状态、版本或通知变动。

实际执行结果由根任务的统一隔离数据库验证记录补充；未把新增测试代码当作已运行通过。
