# 可选手机号密码登录

成员保留邮箱作为主账号，管理员可补录一个手机号作为附加登录标识；两者对应同一成员 UUID、密码、岗位和业务数据。当前交付不补录任何生产手机号，不修改成员密码。

## 管理与接口

后台「组织管理 → 成员账号 → 编辑」新增「手机号（选填）」。当前接受国内 11 位手机号；补录后使用手机号与原密码登录，清空后只保留邮箱。无短信验证码、所有权认证、自助绑定流程。管理员应核对号码归属后录入。

POST /api/v1/console/accounts 与 PUT /api/v1/console/accounts/{id} 支持 phone_number。更新省略字段保留原值；null、空串或纯空格清空。号码首尾空格自动去除。不接收 +86 前缀。现有客户端省略该字段仍兼容。

同公司未删除成员之间号码唯一（停用成员仍保留占用），与数字形式的历史主账号双向冲突也拒绝。邮箱大小写不敏感。跨公司同号在未提供公司时拒绝歧义登录；明确公司时按公司解析，不按密码猜公司。

邮箱/手机号共用账号密码尝试限流和管理员解锁入口。账号编辑撤销旧会话，登录期间对成员行持锁，避免号码删除与发放会话之间的竞态。权限检查及会话撤销均限制当前公司；运营不能管理管理员会话，平台托管身份不能修改。撤销发生在更新角色之前，支持公司存在第二名管理员时合法降级自己。

## 数据库

新增 V103，增加可空 phone_number、唯一索引、跨标识冲突保护及受控解析/撤销函数。不改已应用迁移。撤销函数固定 search_path 并校验当前管理身份和目标公司，部署 owner 应与 set_account_password 一致（当前为 postgres），不能仅依赖 SECURITY DEFINER 假设绕过 FORCE RLS。

## 验证

- 45 项契约、密码、限流及 OpenAPI 单测通过。
- 39 项非 bypass RLS 的 PostgreSQL 集成通过，含补录/省略保留/更换/清空、邮箱与手机号同身份、旧号码失效、旧 refresh 拒绝、共用限流、重复冲突、跨公司歧义与权限限制，以及管理员自降级。
- 两独立数据库连接验证：登录先持锁，管理员改号等待，登录提交后旧会话撤销；号码与数字账号并发冲突拒绝。
- 浏览器隔离夹具验证编辑、保存回显、清空提交 null，无 JS 错误；截图已检查。
- 生产号码保持空值；手机号实际登录验证来自隔离数据库，不代表已为任何真实成员启用手机号。
