# 跨模块当前资格与异步落库核对

本轮保持现有权限、任务归属、人工审批和风险处置规则；不部署到生产。

## 个人风险分析的异步来源

原实现会在落库前复核权限版本，但没有复核模型读取的业务字段。在模型运行期间补充拜访下一步、修改客户等级或商机金额，权限版本可以不变；迟到结果仍可能新建风险，或覆盖尚未关闭的已有风险。

现在个人风险事实读取和落库复核复用同一份字段与筛选口径：本人近 180 天的已确认/归档拜访，最多 12 条，继续受当前 RLS 和 `agent.personal_risks` 范围控制。写入事务锁定本次来源客户、商机和拜访，再比对实际推理字段。来源已修改、删除、移出时间范围或不可访问时，结束本次旧分析并提示按当前记录重新分析；不保存风险或成功卡片。

未进入本次推理的辅助字段变更不会使结果失效。上海时间与 UTC 表达同一时刻时视为同一事实。已有 `accepted` / `resolved` 风险仍按原流程保护；风险负责人仍来自当前运行人，模型不获得指定负责人权限。

## 目标审批的当前申请资格

历史单指标审批原来只核对申请人是否启用，新版整单审批还会核对有效角色和 `target.submit`。旧入口应执行相同的当前资格检查，不能因历史申请仍在就恢复已撤销的提交权限。

同时，个人目标的 `team_id` 固定为空；团队范围的提交权限应按目标人员当前有效团队判断。直接把空 `team_id` 传入授权判断，会错误拒绝仍有团队范围权限的主管。单指标、整单审批统一沿用 `authorization_subject` 的当前人员/团队口径，不扩大团队范围，不改变 deny 优先级。

历史申请人、原金额、原版本不回写；审批人权限、审批对象范围、版本冲突、周期锁和落库状态机保持原样。迁移由主任务以独立数据库子任务审阅；本文件不代表已经上线。

## 管理台弹窗与提交

任务详情/交接、账号权限、客户建档/归属核对、商机详情/编辑/创建、目标配置/历史、业务操作详情、模型发布历史、公司导出选项，打开前都绑定发起读取时的账号、公司、页面和最近一次开窗操作。后点的窗口生效，先前迟到的数据和错误不再覆盖它。商机创建的两个并行目录读取共用一次上下文，避免相互失效。

共享表单提交绑定原窗口与身份。提交期间保留在途锁并暂停编辑，旧回执不会关闭或刷新新的表单；失败后仍可按原流程重试，继续使用既有幂等键。任务历史优先显示事件记录的操作人姓名，当前负责人仍读取当前 assignee。

以上不新增 API、请求字段或权限；浏览器测试使用可控延迟响应验证时序，不代表真实浏览器逐页面验收。

## 验证入口

- `tests/integration/test_personal_risk_source_freshness.py`：模型期间改字段/删除/越过时间范围，分别覆盖新建和已有风险；失败时不写风险、事件或成功消息。包含时区等价与无关字段修改正例。
- `tests/integration/test_target_current_applicant_authorization.py`：撤销提交权限、角色过期、账号停用时拒批；仍有团队权限的换岗账号可批准个人目标，历史快照保持不变。
- `tests/system/verify_cross_module_robustness_postgres.py`：新建一次性 PostgreSQL 数据库与非 bypass 角色，运行上述回归及已有客户认领、目标和拜访权限测试，结束后销毁数据库。
- `frontend/tests/console-dialog-races.test.js`（仓库根目录）：连续选中、关闭、换页、换账号/公司、重复提交、迟到错误、并行目录及历史/当前姓名分离。

所有测试素材均为隔离合成数据；不读取生产账号或模型密钥，不调用真实 AI。
