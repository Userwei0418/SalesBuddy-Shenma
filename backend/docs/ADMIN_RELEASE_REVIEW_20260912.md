## 审核通过后的部署顺序

1. 固定已提交源码完整SHA及归档校验。核对current仍为`agent-report-20260912-7b2c6b9`、数据库V054；若变化先重新比对，不能覆盖并行发布。
2. 持同一部署锁创建新release和独立运行时，先检查导入路径及配置基线。不要复用旧Agent专项发布脚本，它们包含过期release和Agent开关变更。
3. 等待运行中的业务结束，停止API/Worker写入。在服务器生成备份，校验非空、pg_restore目录、fsync及原子落盘；不读取/下载备份内容。失败且迁移未开始时恢复旧服务。
4. 通过统一迁移器执行V055–V060，再运行要求全部unchanged；应用受限身份验证公司规则基线、管理员/运营权限和审计查询。迁移失败保持维护状态，核对账本后修复，不能盲目启动旧代码。
5. 原子切换release，启动API/Worker，检查公网live/ready、真实后台只读页面和基线；验证新业务审计及原API兜底时使用已授权测试范围。确认新发布版本实际生效再声明上线完成。
6. 小程序重新编译并检查旧基线（倒序、问数隐藏）、评分阈值与历史卡片；新自定义规则在客户端验收后才发布。后台页面发布不等于小程序已更新。
