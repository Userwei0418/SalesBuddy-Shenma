# 飞书真实联调与测试记录归档

适用范围：用户授权的一组明确标注“飞书联调测试”的客户、商机和正式跟进，及本次新建的联系人。只向配置确认的 `test-new-crm` 发三类新增卡片。原 CRM-V3、既有真实客户和其他公司不作为测试写入对象。

## 当前进度与执行门槛

572 条初始化全量 ID 对账已通过，见 `evidence/initial-id-reconciliation-20260919.json`。三类新增卡片已在 test-new-crm 群内实际核对，客户/跟进非新增事件的静默同步已核对；测试组退役及远端归档尚无完整生产验收证据。最新发布范围、结果与未覆盖项见 [上线与通知验收交接](RELEASE_ACCEPTANCE_20260919.md)。以下是归档操作规范，不代表已经执行。

归档工具必须先通过 V108 的独立数据库审查和真实普通运行角色测试，再部署和执行。当前后端入口只调用 `security.feishu_test_archive`；不保留通用 SQL 扫描和直接修改四表的备用路径。

此前隔离 PostgreSQL 检查发现：

- 商机 `SELECT` 策略要求 `deleted_at IS NULL`，普通角色直接软删除会在新行可见性校验失败。先删除子对象仍不能解决该限制。
- 普通管理员受通知接收人和 AI 建议所属人的 RLS 约束，因此管理员查询为空不能证明不存在依赖。
- `customer_ownership` 没有创建时间列；`updated_at` 不能冒充创建证据，必须核对同事务创建审计。
- 运营/管理员可创建客户，但没有正式拜访录入能力。清单应记录每个对象的实际创建人，不能把四类对象的身份统一改成维护人。

## 创建与验收

1. 冻结唯一 run ID，并采用 `飞书联调测试-<run_id前8位>` 标识。客户、商机、联系人名称以此开头，正式跟进内容包含此标识。所有文字明确为测试，不伪造真实合同、财务实绩、公司审批或客户承诺。
2. 通过正常管理/业务入口创建。公司建档依据必须如实记为授权测试依据；不得伪造已批准的真实公司编号。正式跟进仍执行真实 AI 质检和确认保存门禁，禁止制造通过分数或审核回执。
3. 分别保存创建 API/维护事务的 request ID、实际 actor UUID、对象 UUID、时间、当前版本。公司、对象关系必须一致。任何失败只处理已成功创建的精确子集，不用名称搜索批量归档。
4. 保存通知配置后重新检查连接，再启用。通知仅新增客户/商机/正式跟进；联系人、其他扩展对象、更新和历史不通知。
5. 对每次新增记录保存：系统提交时间、outbox 事件、远端 record ID、关联 record ID、群卡片消息 ID/回执和时间。群中核对三张卡片及目标对象链接，不把发送 API 返回成功单独当作可见验收。
6. 修改同一组测试对象，验证飞书原记录更新、ID 不变、关联正确、没有多发卡片。分别报告真实提交到同步/卡片的时间，不用队列空闲或接口健康推断实时延迟。
7. 等关联后台任务结束，核对是否出现待办、风险、经营建议和个人能力任务。不得把共享的个人任务当成本条测试私有任务删除，不把任务状态伪改为成功。

## 精确归档清单

清单文件是创建回执，保留在受控运行目录，不提交含业务 ID 的生产清单。顶层含 `workspace_id`、本轮发起人 `creator_id`、`run_id`、有时区且不超过24小时的 `started_at/ended_at`、归档原因 `reason`、`records`。

每条 `records` 必须包含：`kind`（customer/opportunity/visit/contact）、精确 `id`、当前 `version`、实际 `creator_id`、原创建 `creation_request_id`。只能一个客户、至多一个商机和跟进；跟进必须有商机。只允许显式列出的本次联系人。

为验证修改静默同步而产生的正常编辑，须另列 `mutations`（最多16条，逐条 `request_id`、`actor_id`）。数据库须以本组对象真实 UPDATE 审计验证这些回执；不能把创建时间窗口内的任意修改当成本轮授权。当前版本与精确修改回执同时核对，保留修改产生的业务变更/预测证据。

使用现有 API 服务普通数据库登录和现有管理员身份。首次只生成计划：

```bash
uv run python scripts/archive_feishu_test_records.py \
  --workspace sensetime-ecosystem --administrator OPSADMIN \
  --manifest /受控运行目录/本次回执.json
```

检查计划中的精确对象、保留证据、阻塞依赖后，使用本次返回的摘要执行：

```bash
uv run python scripts/archive_feishu_test_records.py \
  --workspace sensetime-ecosystem --administrator OPSADMIN \
  --manifest /受控运行目录/本次回执.json \
  --apply --expected-plan '本次dry-run返回的plan_hash'
```

CLI 将专用归档语句限制为5秒、锁等待500毫秒；数据库 apply 使用 NOWAIT 获取短暂依赖锁，执行完立即提交，禁止事务内等待网络。遇到忙或依赖变化先退出，重新核对计划。

不接受超级用户、BYPASSRLS、表所有者或飞书 Worker 代替普通运行角色。实际归档由严格校验的专用数据库入口完成，不放宽正常业务策略。任一身份、回执、版本或依赖变化均须整体拒绝或重新生成计划。

## 归档后的证明

按精确 ID 核对本地软删除与逐行审计，保留原创建人、确认时间、跟进原始快照、业务审计和飞书发送回执。验证飞书对应记录转为“已归档”，没有重复新增通知。分别核对任务、风险、建议、通知及个人评分等派生影响；仅列表看不见不等于全部影响已清理。
