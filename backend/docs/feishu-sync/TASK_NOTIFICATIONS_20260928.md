# 任务派发群通知

管理员在后台确认发放的周任务沿用客户、商机、跟进记录的飞书群通知通道。任务仍由 SalesBuddy 保存和执行；飞书 V4 显示当前状态，群卡片提示新增任务。

## 开关与路由

- 公司后台「飞书同步」增加「周任务发放通知」。只有通知总开关、任务表映射、任务通知选择及同步连接均启用时，新任务才通知。
- 配置为 `notification.on_create` 包含 `task`。旧配置和默认配置仍只选客户、商机、跟进记录，不自动启用任务消息。
- 统一群模式使用已有默认群。按部门分群模式使用当前有效负责人的部门；岗位任务使用有效待领取人员的部门，同一个群只发一次。没有匹配的部门路由时，按现有规则使用默认群。
- 使用接收人的分组，不使用下发人的部门。无有效接收人的任务不会发群卡片。

## 生命周期

- 仅服务端验证的管理员后台会话，在周会批量确认时产生的正式任务可通知；仅凭客户端字段、任务标题或 `source_code` 不足以触发。
- 成员之间直接分配、小程序创建、业务建议下发、普通成员批量导入均不通知。周会解析和草稿也没有通知。
- 卡片展示任务名称、内容、负责人或待领取人员、下发人、北京时间截止、中文状态、来源批次及 V4 当前任务链接。
- 领取、完成、取消、转交等变化继续同步 V4，不额外发新增卡片。既有群卡片是派发时提示，查看详情以当前表格和小程序状态为准。
- 历史同步不通知。V195 将既有未规划的任务首次事件标为历史；关闭任务通知期间创建的任务，稍后开关打开也不补发。
- 首次处理按当前有效任务和接收人规划卡片；取消、完成、待验收或待交接的任务不产生新增通知。卡片规划冻结后、实际发送前再次核对，若任务、接收人、分组、正文或期限发生变化，阻止旧卡片并留下失败原因。
- 复用持久化投递记录。同一任务/群去重，明确可重试的失败沿用原投递标识，结果未知的发送保留人工核对状态，不盲目重发。

## 部署与验收

V195、API/后台静态资源和飞书 Worker 一起发布。迁移期间停止旧 API 写入和两个 Worker，避免旧捕获函数与历史隔离步骤并发。数据库仅替换两份现有函数体、标记历史任务事件并登记版本；函数 OID、所有者、权限和业务任务不变。

本地验收使用 `database/tests/verify_task_group_notifications_postgres.py`：独立 PG16 私有 socket、真实受限 Worker 身份和队列仓储，网络采用记录型假传输。覆盖跨公司隔离、当前负责人分组、岗位候选人、历史不补发、去重和发送前取消。真实飞书发送必须另行记录生产接口回执，不能以本地测试冒充实际送达。

本次不改变小程序接口或源码，不需要重新上传小程序。原有周会草稿保持原状。
