## 为什么新版不依赖 Base Workflow 发群通知

- 原 CRM-V3 的 Workflow（新增记录→延迟→查找→发送飞书消息）只是一种飞书侧编排方式，不是消息能力本身。新版由系统数据库写入触发受控 outbox，专用 Worker 先把同一事件写入目标 Base，再按已冻结的通知计划调用飞书 IM `messages` 接口发送交互卡片。
- 通知计划在系统侧生成并持久化，包含公司、连接版本、对象类型、对象 ID、目标群和幂等键；worker 租约、失败重试、结果未知人工核对、修改静默、历史不通知和部门路由都在系统侧控制。因此没有 Base Workflow 也能完成群通知，且不会被用户在 Base 中编辑记录反向驱动系统。
- 飞书 Workflow 仍可作为客户侧的补充编排工具，但不能作为系统同步或通知的唯一事实来源；若与后端同时开启同一条新增通知，会产生重复卡片，所以新版不在目标 Base 复制旧版 Workflow。
- 当前通知开关仍关闭。启用前必须完成真实新增客户/商机/正式跟进三张卡片、修改同记录不重复发卡片、历史初始化不发卡片以及 `test-new-crm` 群内可见性核对。未完成这些真实证据前，不把权限校验或单测通过称为群通知验收通过。
