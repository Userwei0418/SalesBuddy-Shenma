## 接入行为

沿用现有客户更新、商机变动或拜访归档所触发的 `battle_map.review` 任务。后端按当前身份读取客户、拜访、联系人和商机事实，再选择作战地图中台 Agent 或原 SenseAudio API。中台超时、错误、无效结果或受控阻断时，在同一次评估中自动转原 API。两个提供方均无法完成时返回明确失败，保留此前有效评分，不保存伪造结果。

两个提供方共用现有评分归一化与证据 ID 校验；合法数字/数字字符串兼容原调用，保留原 0–100 截断及一位小数处理，同时拒绝布尔值和非有限数，避免 NaN 被错误归一为有效评分。只接受当前输入中存在的证据来源。象限继续由后端的既有 70 分阈值计算，忽略模型声称的象限、提供方或调用轨迹。

Agent 只返回评分和依据，不直接访问数据库，也没有查询或写入工具授权。后端沿用原评分保存、历史有效期、业务重评完成和拜访归档通知流程；客户或商机的人工修改与确认流程不变。结果写入前再次确认客户仍可见；任务执行资格检查继续使用既有租约机制。

调用提供方、兜底原因、operation ID、任务 ID 和中台运行标识放在评分输入快照的私有 `inference_route` 中。前端接口只读取既有分数和象限，不暴露这些诊断字段。没有新增前端入口、API 或数据库迁移。

## 独立开关与绑定

- `AGENT_FDE_BATTLE_MAP_ID` 和 `AGENT_FDE_BATTLE_MAP_API_KEY` 只供作战地图使用，不能复用问数 API Key。
- 绑定配置 `AGENT_PLATFORM_BINDINGS_JSON` 的工作空间下新增 `battle_map_review`，执行方式为 `filtered_facts`，记录发布回读的 `expected_snapshot_id`；不声称运行 API 能证明实际快照。
- 试点采用原 `AGENT_FDE_PILOT_PATH` 或 JSON 配置，但作战地图必须显式出现在该工作空间的 `capabilities.battle_map_review` 下，单独设置 `enabled`、`user_ids`、`expires_at`、`block_platform_requests`。旧的问数平面配置不会开启作战地图。
- 关闭、配置缺失、过期或不在白名单内时，继续原 API。阻断只在授权测试账号和时段生效，不发送中台请求，不伪造中台 HTTP 错误。
- 用户追加确认：本项业务验收通过后正式启用，无需关闭。该工作空间的 `capabilities.battle_map_review` 设置 `enabled=true, rollout=production` 即持续启用，不依赖试点到期时间或测试账号名单。生产模式忽略测试阻断标志；运维仍可将 `enabled=false` 原子切回原 API。此授权不改变问数隐藏入口及 MCP 二期范围。
