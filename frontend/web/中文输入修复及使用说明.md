# SalesBuddy Web 中文输入修复及使用说明

修订：**1.1.1-web.1+ime.1** · 2026-09-30  
基准：本次提供的 `web-frontend (1).zip`（1.1.1-web.1）。本次是 Web 输入修订，不是中后端或小程序版本升级。

## 这次修复了什么

中文输入时，旧 Web 适配层在下一帧才把业务状态传回 React，输入框会先恢复旧值，打断拼音组词。原包在拜访记录、拜访客户搜索、任务描述、客户认领搜索中，模拟输入“你好”得到 `nninihao你好`。

- 新增共用输入适配组件：即时回显，组词期间保留候选文本，完成组词后调用原业务方法，避免重复提交同一次输入。
- 接入文本框、多行文本、搜索、账号／密码、弹窗输入；保留现有 Ant Design／Sb 组件与视觉样式。
- 选词用的回车不触发页面搜索或表单提交；确认文字后正常回车仍可搜索。
- 保留清空、字数上限、数字格式化、光标位置、草稿恢复与语音回填。原生回退页面也增加组词保护。
- 跟进确认页的可编辑字段改为读取当前 `values`，避免读取旧字段快照而恢复原文。

没有修改服务端接口、权限规则、金额单位、任务状态、小程序或管理后台，没有升级或新增依赖，没有自动部署。`source/miniprogram/`、锁文件、服务配置与原包一致。

## 包内内容

完整目录位于 `frontend/web/`：

- `department-ui/`、`runtime.js`：修订源码。
- `dist/`：已构建页面，可直接运行或用于部署。
- `IME_FIX_RELEASE.json`：本次修订标识、原包校验值、变更列表与构建文件校验值。
- `tests/ime-input.browser.mjs`：本次中文输入回归脚本。
- `docs/ime-fix/`：最终检查日志、截图、验证结果。
- `.history/`：可读取的覆盖前备份及中间验证记录；原始校验清单为 `.history/original-manifest.json`。

包内原有 1.1.0／1.1.1 发布和验收资料作为历史来源保留，本次输入修订以本说明及 `IME_FIX_RELEASE.json` 为准。包内不含 `node_modules`。

## 本地打开

需要 Node.js 22 或更新版本。终端进入解压后的 `frontend/web/`。使用已有 `dist` 不需要先运行 `npm install`，也不需要 Python。

**先看隔离演示：**

```sh
PORT=5189 node scripts/start_department_preview.mjs
```

浏览器打开 `http://127.0.0.1:5189/?mode=preview#/pages/index/index`。页面标有合成数据演示，不访问真实业务后端。按 Ctrl+C 停止；端口占用时换一个 `PORT`。

**连接原有企业环境：**

```sh
PORT=5188 node server.mjs
```

打开 `http://127.0.0.1:5188/?mode=live#/pages/login/index`，使用已授权企业账号。后端地址沿用原 `connection.config.json`；保留部署环境已有的 `SALES_WEB_API_TARGET` 等设置。本次没有附带或修改账号、密码。

macOS 也可在 `frontend/web/` 双击原有 `启动小浣熊SalesBuddy.command`。不要直接双击 `dist/index.html` 以 file 协议打开。

## 替换线上 Web 与回退

1. 先备份当前线上 Web 静态目录及环境配置，保留上一份可运行包。
2. 部署人员将本包 **完整 `frontend/web/dist/` 的内容**替换到原 Web 静态目录，保留原网站路由、同源 `/api/v1` 代理与运行环境配置。不要只替换某一个 JS，也不要覆盖中后端目录。
3. 按原部署方式刷新静态资源缓存，确保 `index.html`、`entry.js`、`runtime.js` 及 `department-ui/app.*` 来自同一个包。部门 UI 文件已有新构建标记。
4. 在原企业入口使用实际浏览器及中文输入法验证：输入 `nihao` 选“你好”，继续输入中文，测试删除、插入、搜索、弹窗与草稿恢复。应只留下确认后的文字，选词回车不误提交。
5. 如需回退，恢复上一步保存的完整 Web 静态目录并刷新相应资源缓存。没有数据迁移或后端回滚操作。

实际中文输入入口与截图均在 `docs/ime-fix/verified/`：

- 拜访与跟进：客户搜索、原始记录、确认页的沟通内容／下一步计划／首次拜访补充；对应 `visit-search.png`、`visit-note.png`、`visit-confirm.png`。
- 客户：列表搜索、认领搜索、创建客户名称、维护联系人与伙伴；对应 `customer-search.png`、`claim-search.png`、`customer-create.png`、`customer-edit.png`。
- 商机：列表搜索、商机名称与 ACV；对应 `opportunity-search.png`、`opportunity-create.png`。
- 任务：描述、人员选择、协调原因与取消弹窗；对应 `task-description.png`、`person-picker.png`、`task-detail-inputs.png`。
- 登录账号、390px 窄屏和原生回退：`login-account.png`、`narrow-visit-note.png`、`native-visit-note.png`。

核心预期和实测均为：`n → ni → nihao` 始终是一段未确认的组词，确认后只得到“你好”；输入期间刷新无关状态也不重置文本或焦点。专项还验证了中英文混输、光标插入／删除、清空撤销、草稿重载、异步回填、字数边界、正常搜索回车，以及弹窗关闭后焦点返回。

首次拜访专项在合成测试账号中单独设置可用权限以覆盖该分支，未改变产品权限判断。测试没有向真实企业环境创建业务记录。

**验证边界：**上述结果证明本地浏览器页面和输入处理。没有操作用户电脑的 macOS／Windows 输入法候选窗，也没有登录线上账号或发布到线上；真实输入法、生产环境仍需部署后按上面的实际入口复核。语音测试为字段回填，不是实际录音转写。
