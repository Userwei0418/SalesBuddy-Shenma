# SalesBuddy PC Web 1.2.0 改造说明（PC 视觉 2.0）

日期：2026-10-06　基线：交接包 `bfa37f4`（`codex/active-filter-team-scope`，Web 1.1.2）　本版：Web 1.2.0

## 一、先看结论

- **PC 是主要工作平台**：侧栏改成「一级模块 ＋ 子菜单」，PC 覆盖全部功能；手机宽度仍保留原来底部五个入口，小程序继续负责移动端快速录入与反馈。
- **视觉**：主色改为浅蓝 `#3370FF`，侧栏改浅色，正文 14px、表格 13px、页面标题 18px、指标数字 24px，控件高 32px，整体密度参考飞书。
- **新增四个 PC 模块**：工作台（替换原总览）、跟进记录、工作报告（日会 / 周会）、知识库（方案与定价、客户档案 Playbook、方案生成）。
- **不改接口**：小程序业务源码（`source/`，与交接包逐字节一致，构建冻结校验通过）与 `utils/apiClient.js` 一行未动；新模块只调用 `apiClient` 里已有的读接口，没有新增、修改后端接口，也没有新增写操作（修改密码复用原有 `POST /auth/password`）。
- **验证范围**：构建、单元 / 契约测试、本地演示数据下的浏览器检查（结果见 [验证记录](验证记录.md)）。**未做真实后端联调与生产验收**；演示工作区的数据全部为合成数据。

## 三、四个新模块

### 1. 工作台

- **时间**：今日（默认）/ 本周 / 本月 / 本季度，北京时间，周一为一周开始。
- **范围**：个人 / 团队 / 成员。能看团队的身份默认看本人团队（总经理默认全部团队）；一线销售默认看个人，可切到本人所在团队（需求清单第 23 条）。团队与成员下拉都支持模糊搜索与拼音首字母。
- **内容**：跟进次数与活跃人数（有跟进记录的成员）、活跃客户、新增商机、待办与已完成任务（保留原总览「今日待办 / 全部待办 / 今日已完成」三个入口，点开即原任务页的同名筛选）、风险；成员跟进分布（零跟进标黄）；活跃商机列表（有跟进记录的商机）；业务动态（原首页动态流原样嵌入）；快捷操作。
- 能创建任务的身份在活跃商机上可「发起售前」：带着客户与商机进入原「创建任务」页，接收人可选 FDE（售前 / FDE 自己看时这个入口叫「创建任务」）。

### 2. 跟进记录（拜访与跟进）

- **视角**：按时间 / 按人 / 按客户 / 按商机 / 表格。时间与范围与工作台一致，另支持当年内的自定义日期区间。
- **规则**：本人的全部跟进 ＋ 有权限团队成员的跟进，与小程序跟进记录同一套数据（第 26、27 条）。点客户名进入客户详情时间轴；点记录进入原拜访详情。
- **来源**：记录带 `source_system` / `source` / `origin` 为 `projectbuddy` 时标「ProjectBuddy」；记录人是售前或 FDE 时标「售前 / FDE」。
- **导出**：表格视角可导出 CSV（UTF-8 BOM，Excel 直接打开），替代多维表格的日常整理（第 27、28 条）。

### 3. 工作报告

- 日报（今日）与周报（本周），个人 / 团队 / 成员三种范围。
- 内容：关键数字、每个成员的跟进与进展卡片、新增与推进中的商机、已完成与待办任务、风险。
- **会议模式**：全屏逐页展示（键盘 ← → 翻页、Esc 退出），用于日会、周会。
- 「复制」「下载」（Markdown）：按固定模板汇总已录入的事实，**不做 AI 推断**，文末注明数据口径与生成时间。

### 4. 知识库

- **方案与定价**：按类别（解决方案、产品定价、案例与资质、模板与话术）与产品线筛选，搜索标题 / 摘要 / 标签（支持拼音首字母）；默认只看当前版本，可切到「含历史版本」；定价显示有效期与审批规则。
- **客户档案 Playbook**：选客户后汇总客户概况、联系人与角色、商机、跟进时间轴、待办、风险、相关方案；有 `advice.request` 权限时可调用原有业务建议接口生成 AI 建议。可复制或下载档案。
- **方案生成**：选客户、商机与方案模板，按「客户背景 → 需求与现状 → 方案概述 → 应用场景 → 实施路径 → 商务建议 → 下一步」生成可编辑草稿，可复制或下载。
- **数据来源**：演示工作区使用 `department-ui/pc/knowledge-sample.js` 的虚构示例；企业工作区读部署目录的 `knowledge/catalog.json`（随包为空模板，维护方法见 `knowledge/README.md`）。后端有知识库接口后，只需改 `department-ui/pc/knowledge-data.js` 的 `loadCatalog`。

## 四、各模块调用的接口（全部为原有接口）

| 模块 | 用途 | `apiClient` 函数 | 接口 |
| --- | --- | --- | --- |
| 工作台 / 跟进记录 / 工作报告 | 成员与团队 | `getDirectoryMembers`、`getTeamDirectory`；FDE 身份用 `listFdeMembers` | `GET /directory/members`、`GET /directory/teams`、`GET /directory/fde-members` |
| 同上 | 有跟进的客户 | `getCustomerMap({activity_window})` | `GET /customer-assets/map` |
| 同上 | 每个客户的跟进 | `listVisits({customer_id})` | `GET /visits?customer_id=…` |
| 同上（FDE 身份） | FDE 跟进 | `getFdeActivity({date_from, date_to})` | `GET /fde/activity` |
| 同上 | 任务 | `listTaskPage({tab, view, member_id})` | `GET /tasks` |
| 同上 | 活跃 / 新增商机 | `listOpportunities({activityWindow, scope, teamId, ownerId})` | `GET /opportunities` |
| 同上 | 风险 | `listRisks()` | `GET /risks` |
| 知识库 · Playbook | 客户档案 | `listCustomers`、`getCustomerOverview`、`listCustomerContacts`、`listCustomerOpportunities`、`listVisits`、`listDetailTasks`、`listRisks` | `GET /customers`、`/customers/{id}/overview`、`/customers/{id}/contacts`、`/customers/{id}/opportunities`、`/visits`、`/tasks`、`/risks` |
| 知识库 · Playbook | AI 建议（可选） | `queryBusinessAdvice('customer', id)` | 原有 `/advice` 接口 |
| 个人中心 · 账号设置 | 资料与改密 | `getCurrentActor`、`changePassword` | `GET /auth/me`、`POST /auth/password` |

`getCustomerMap`、`listOpportunities` 是原 `apiClient` 的「目录读取」，调用前会先取 `GET /metadata/business-options`，行为与原页面一致。

**跨客户聚合的限制**：`GET /visits` 必须带 `customer_id`，没有按时间、按人跨客户查询的接口。因此跟进统计先用作战地图接口按时间窗筛出有跟进的客户，再逐个客户读取跟进（并发 4，最多 400 个客户，按最近跟进时间排序后提前停止），60 秒内复用结果；离开页面、切换时间或范围时立即停止读取，不在后台继续发请求。客户超过 400 个时，页面口径行会注明「客户较多，已读取最近活跃的前 400 家」。本季度没有对应的 `activity_window`，先取作战地图范围内的客户，再逐个核对跟进日期。

### 商机管理本轮边界（Web 1.2.0 增量）

- 商机管理默认读取当前账号的全部商机，默认范围为「我的」、跟进时间为「全部跟进」；列表先展示仍在推进的商机，再按接口返回的季度分组，季度分组不会因为页面倒序而把丢单记录置顶。
- 列表支持本机自定义可见列，当前仅使用接口已有字段：商机 / 客户、阶段、负责人、ACV / 金额、签约方式、状态、确收 / 回款、预计关单、产品线。没有对应字段时显示「未填写」或「未登记」，不在前端推断业务值。
- 支持保存、切换、重命名、删除个人视图。视图只保存在当前浏览器的 `localStorage`，键按工作区与账号身份隔离，不写后端、不在账号之间共享；清理浏览器数据或换设备后需要重新配置。当前视图保存可见列配置，页面筛选仍由原有接口与筛选控件负责。
- 本增量没有新增后端字段、数据库迁移或线上部署；签约方式只映射已返回的 `sales_channel` / `partner_name`（直销、伙伴转售），未知值保留为「未填写」。

## 六、给后端的建议（不在本包实现）

1. **跟进按时间与人员跨客户查询**：`GET /visits?date_from&date_to&recorder_ids&team_id`，可替代第四节的逐客户聚合，统计更准、请求更少。
2. **知识库接口**：`GET /api/v1/knowledge/items`（字段与 `knowledge/catalog.json` 一致：类别、版本、状态、有效期、价格明细、审批规则、附件），由运营后台维护版本。
3. **ProjectBuddy 同步**：对应 ProjectBuddy《业务逻辑设计 v3.2》的「01 发起」（销售在 SalesBuddy 商机上发起售前任务）与「06 回流」（售前记录确认后回写 SalesBuddy 跟进记录）。回写的跟进记录带 `source_system: "projectbuddy"`（或 `source` / `origin`）即可，Web 已按此字段标注来源；同步接口与去重规则需双方另定。
4. **个人资料修改**：邮箱、手机号、头像的更新接口（第 24 条）。
5. **团队可见范围**：一线销售读取本人团队、以及「团队 ＋1 主管能看的客户销售也能看」的规则需在后端权限中落地；Web 只按接口返回的范围展示。

## 七、已知限制

- 未用真实账号联调；真实权限、真实数据量下的性能与统计口径以联调结果为准。
- 跟进统计受第四节的聚合方式限制（最多 400 个客户）。
- 工作报告、方案生成、Playbook 的文本由模板汇总已录入事实，不是 AI 生成；Playbook 中的 AI 建议来自原有业务建议接口。
- 知识库企业工作区需要先维护 `knowledge/catalog.json`，否则显示空状态。
- ProjectBuddy《业务逻辑设计 v3.2》写明其 UI 沿用 SalesBuddy PC Web 版式（藏青侧栏、白色顶栏、灰底卡片）；本次按用户要求把 SalesBuddy 侧栏改为浅色，两边是否统一请另行确认。
