## 1. 已对齐的系统边界

| 事项 | 当前口径 | 对本轮开发的影响 |
| --- | --- | --- |
| 环境 | 本地开发/验收环境与线上运行环境分开；先本地验收，再考虑同步线上 | 本轮只改本地源码和接口契约，不发布线上 |
| 端 | PC Web 是本轮主入口；小程序保留轻量看板和移动端快速录入 | Web 可以增加小程序暂时不用的只读接口，但不能破坏共用接口 |
| 服务 | Web、小程序共用后端；Agent 中台是独立的后续接入面 | 先打通 Web→后端；Agent/RAG 不冒充已完成能力 |
| 页面结构 | PC 统一为“一级模块 + 子菜单 + 顶部筛选/指标 + 下方可滚动内容区” | 当前包的导航、工作台、跟进记录、工作报告、知识库作为候选实现接入 |
| 验收顺序 | 构建/单测 → 本地后端 HTTP → 真实账号权限/数据 → 视觉验收 → 线上同步 | 合成数据通过只能证明前端结构，不能证明真实业务完成 |

## 5. 当前接口接入结果和边界

已做的接口兼容改动：

- `VisitSummary` 增加客户、商机、记录人、岗位快照、来源系统、FDE/协同人、目标、时长等 Web 需要的可选字段；
- 历史跟进查询补齐这些字段，并保持旧字段兼容；
- Web 兼容 `recorder_id` / `recorder_user_id`、`recording_role_code_snapshot`、`severity_code` 和来源字段；
- Web 的季度/全部时间范围显式映射为年度读取窗口，避免后端默认退回“今天”。

当前还不能称为“真实后端已验收”：

- 本地后端启动被既有数据库迁移 `V193` 的 checksum 不一致阻断，尚未重置、跳过或修改迁移；
- Web 包原有的 141 项测试和构建使用合成数据/隔离模拟接口；
- 真实账号权限、真实数据统计、上传日志、线上运行版本和客户验收均未在本轮完成。

对应的后端字段变更记录见 `backend/docs/WEB_PC_120_INTEGRATION_20261007.md`。

## 6. 推荐执行顺序

1. 先冻结 C1–C4，以及每个模块是否纳入本轮验收。
2. 修复或迁移本地开发数据库的历史 checksum 问题，启动本地 API、Web 和必要 Worker。
3. 用真实本地账号走一遍登录、权限、工作台、跟进记录、商机、报告和知识库空状态。
4. 按真实数据补接口：跨客户跟进、动态知识库、个人资料更新，以及已确认的任务/飞书同步。
5. 做视觉和业务验收，记录页面截图、请求响应、账号角色和未完成项。
6. 用户确认后，再把已完成的变更局部同步到飞书文档；同步后回读 revision，保护人工补充内容。
