## 业务基线与 Web 差异

- 原始 273 个小程序文件的校验记录：source/upstream-1.1.0-manifest.json。config.js 原文另存 source/upstream-1.1.0-config.js.txt。
- 原生目录唯一差异为 config.js 的 API_BASE_URL 改成同源 /api/v1，保留 HOME_CHATBI_ENABLED=false 和 HOME_MESSAGE_ORDER=desc。其余 272 个文件与原包一致，构建逐一验证。
- Web 必需的适配保留在 scripts/web_*、department-ui、runtime.js、browser-platform.js 和 shell.js；组件事件桥接调用原生 Page/Component 方法，不改写校验与状态机。构建产物允许与原生模板不同。
- 新版任务取消和人员选择组件采用 Ant Design 弹窗承载；二次原生确认期间释放底层焦点限制，关闭后恢复正常焦点。
- 经营分析不使用 department_sales；最新源码要求 contract_version=2、data_source=database，以及 peer / company_teams 范围，Web 保留该校验。
- 周报 Demo、创建客户连续填写、移除语音、全宽进度保持原交付行为。其他页面已有语音入口继续保留。

## 公司规范采用与边界

沿用 React 18、Ant Design 6、Ant Design X 和现有 @shandiant 组件与锁文件；没有升级依赖。采用 P-01/P-03、V-01/V-03、C-02/C-06/C-07、B-02/B-04 与 X-01/X-06：深蓝导航、浅色工作区，主要控件使用 --ui-primary、--ui-space-*、--ui-radius-control；错误保留输入，权限来自服务端。桌面高密度列表，窄屏地图与列表上下排列。

沿用 1.1.0 中的状态机确认文案及历史底层样式，不为统一措辞修改冻结业务文件。全量屏幕阅读器、触控真机与系统软键盘未验收；见验证记录。合成角色的能力由演示 provider 显式提供，不能作为真实角色授权依据。
