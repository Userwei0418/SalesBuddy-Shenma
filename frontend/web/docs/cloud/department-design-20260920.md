# 部门组件库候选版 · 2026-09-20

## 目标与范围

以当前 Web 评审分支 cd8f7ca 为基线，制作一版实际采用部门 npm 组件库的 Web：总览、客户列表与象限图、任务列表、创建任务四页。通过原业务页面的数据和处理事件操作；详情、认领、商机与拜访继续使用已有页面。第一版是渐进接入的候选方案，尚不代表全站 React 迁移或正式业务验收。

## 方案

- 独立 worktree、分支和预览服务，原 5186 企业工作区和 5187 评审版保持可用。
- 安装公开包 tokens 1.1.0-draft.1、ui-react 0.3.0 与 React 18、Ant Design 6、Ant Design X 2；锁文件固定实际依赖和包完整性。
- 共享原 Page 实例、原数据、原权限与方法。Web runtime 提供展示适配入口，React 只负责这四页的呈现与事件绑定；其他页面自动回到原渲染器。
- 使用真实 SbProvider、页面标题、状态标签、搜索、数据状态、指标和表单组合件；列表及基础控件采用 Ant Design。业务判断来源不变，不把“保存成功”当作“向好”。
- 包中新增跨端变量仍标注草案；本次采用范围限定候选版，已确认的 V1 业务表达及权限规则继续有效。

## 实施步骤

1. package.json / package-lock.json / scripts/build-department-ui.mjs：安装与构建部门组件资源，追加到既有构建链。
2. runtime.js / entry.js / index.html：接入可卸载展示层；按 Page 实例切换，不重建认证或 API 客户端。
3. department-ui/*：四页布局、复用组合件、原事件适配、窄屏与异常状态。客户详情打开时交还原渲染器，保留原详情/地图选择逻辑。
4. scripts/start_department_preview.mjs：单独的纯合成预览，默认5188；不提供企业登录入口。
5. tests/department-ui.browser.mjs：检查角色、总览下钻及状态切换、客户筛选与详情返回、任务创建校验与提交、窄屏与错误状态，保持业务源码校验。

## 风险与验证

现有代码不是 React：不直接替换业务源文件，不修改256份源码清单。特殊语音或组件流程需要通过原事件适配，若某种状态必须回到原页面应明确记录。组件包的属性行为以已下载类型及实现核对，不根据名称猜测。运行 npm run verify，浏览器使用纯合成数据与隔离服务；1366×768、1440×900、390×844 检查。真实认证、后端写入、Agent、生产验收不在本候选版测试结论内。

## 已完成的候选实现

| 页面 | 本次呈现 | 保留的业务行为 |
|---|---|---|
| 总览 | 紧凑指标横排、动态分类与搜索、长回执抽屉 | 当前账号与授权范围；原待办统计、下钻条件、动态按钮及FDE团队入口 |
| 客户 | 顶部资产、共同筛选、左侧象限图与右侧分页表格同时呈现 | 象限缩放、重叠点名单、当前目录权限；原详情与画像；确收/回款独立口径 |
| 我的任务 | 状态标签页、原排序、关联对象和操作对齐表格 | 总览条件可清除；状态切换恢复全量口径；原服务端游标和加载更多 |
| 创建任务 | 左侧任务内容、右侧负责人/优先级/日期、底部提交 | 原校验、客户商机关联、负责人目录、确认下发、失败保留输入 |

客户与任务的分页只切分当前已经加载的数据；任务明确展示“已加载/总数”，仍通过原方法加载下一批。没有用前端页码伪造服务端数据总量。原详情页、认领、商机与拜访未换成这批 React 组件；首页进入语音录入、ChatBI等复杂状态时也回到原展示层。页面卸载时销毁 React 根，返回后恢复原 Page 状态。

修复了一处展示适配中的数据刷新缺口：管理者清除团队/成员条件时，重新调用原 `loadAssets` 更新确收与回款；纯客户列表筛选不改变资产口径。加载时显示“正在读取”，不会把尚未获取的数据当成零或空结果。

按用户后续要求，四象限图恢复原版浅色分区、中央实线、四角说明、图内坐标轴和蓝色圆点。继续保留图表/列表并排、原坐标、象限放大、重叠点选择与筛选联动。

按用户最新要求，常驻解释文案已统一精简，覆盖上述四页及原客户、商机、拜访等页面。具体范围与验证见[页面文案精简](concise-page-copy-20260920.md)。下方截图为当前候选版。客户页进一步收紧资产与筛选、四象限铺满左栏，并按视口高度分页，实测与边界见[客户页空间优化](customer-workspace-20260920.md)。

### 实际包与复用方式

`@shandiant/tokens` 1.1.0-draft.1、`@shandiant/ui-react` 0.3.0 来自用户提供的[公开发布目录](https://github.com/shandianT/desgin/tree/main/release)。React/ReactDOM 18.3.1、antd 6.6.5、Ant Design X 2.9.0、dayjs 1.11.23、esbuild 0.28.2 按 `package-lock.json` 固定。

使用了实际 SbProvider、SbPageHeader、SbMetricTile、SbSearch、SbStatusTag、SbStatePanel、SbField、SbBottomBar、SbPagination；基础表格、筛选、标签页、抽屉与日期采用 Ant Design。Ant Design X 通过包的 Provider 接入，本轮没有重写 AI 对话或增加 Agent 能力。日期控件采用中文 locale。没有 SbTable 导出，因此没有虚构组件接口。

两个发布包的SHA-256：

```text
tokens  9e947cd4d1a2e489f6cdaa23b9cb1241b7af6729c06f775e3644b805f234857d
ui-react 0f2c52262bfabdf893198e61e0d29f9ce6f0851acfe7b31e2c08142e2bcde594
```

锁文件同时校验下载完整性；若上游用同名文件替换内容，应核对变更后升级依赖，不能直接去掉完整性检查。构建输出本地 JS/CSS 和许可文本；页面运行不依赖 CDN，`dist`、`node_modules` 不提交。未压缩的 JS 构建产物约1.1MB，后续全站采纳时可评估按页拆分。

## 运行与交接

```sh
npm ci --ignore-scripts
npm run verify
npm run preview:department
```

以上隔离服务打开 [5188 合成示例](http://127.0.0.1:5188/?mode=preview#/pages/index/index)，从右上角切换示例角色。它主动关闭后端，不能用来登录正式账号。

### 正式账号入口（本轮追加）

用户要求新版支持原企业账号。本机5188现已改用通用 `server.mjs` 启动，读取与原5186相同的后端连接配置：

```sh
# 停止同端口预览进程后，使用企业模式启动；不要同时启动两种服务。
PORT=5188 npm run dev
```

打开 [新版企业账号登录](http://127.0.0.1:5188/?mode=live#/pages/login/index)，使用已有账号密码。账号身份和授权数据仍由原后端返回。URL里的 `mode=preview` 明确表示示例，换成登录入口不会复制或借用其他端口的登录凭据。

本机已验证 `/web-capabilities` 返回 `previewOnly:false`；`/connection-status` 已配置且可达；经新版 `/api/v1/health/ready` 代理返回 `status:ok`。已打开实际企业登录表单，未提交真实账号密码、未进行真实业务写入。这是连接与入口验证，不等同于某个正式账号的登录及授权数据验收。

本轮追加改动后重新通过 `npm run verify`（105项），以及客户/总览和登录模式隔离的23项浏览器回归。四象限恢复后的截图已替换下方客户截图；图表和列表数据源与点击处理不变。

原5186企业服务仍可用。其他电脑需自行运行服务并核对授权后端，本机链接不是线上部署地址。云端设计任务仍优先用隔离的合成预览命令。
