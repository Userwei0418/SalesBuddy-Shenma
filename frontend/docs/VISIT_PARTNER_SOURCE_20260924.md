# 跟进伙伴只填写一次（第 4 项）

状态：代码与本地自动化验证完成；未部署后端、未上传或替换小程序体验版，等待本轮需求改完后统一发布。

## 确认规则和来源

用户确认商机“所属伙伴”和拜访“伙伴名称”指同一个伙伴，批准有商机时复用、无商机时保留一个选填入口。当前独立分支 `codex/visit-partner-single-input` 从已完成 RBAC 的 `0d3c67964c08c13eff66a0f2b2248228a4a4d5a1` 继续；权限改造 PR #30 尚未合并，不能将本项直接覆盖到旧主线后发布。

允许修改 `frontend/` 的确认页、快照和回归，以及 `backend/` 的 FDE 商机选择返回字段、OpenAPI 和相关测试；没有数据库迁移、账号授权或历史业务数据变更。

## 修复行为

- 新建/编辑商机时只保留商机表单内的伙伴选择，下方重复输入隐藏。
- 只关联商机或 FDE 选择本人参与的商机时，伙伴只读显示并来自服务端当前商机；直销显示“直销”，未知保持为空，不从原文或其他商机猜测。
- 未关联商机时仍可选填伙伴。该手工值单独留在草稿内，选择商机不会覆盖它；取消关联后恢复原值，各商机自己的草稿互不串用。
- 页面显示、AI 质检字段和归档请求共用同一个伙伴来源。伙伴改变会使已有质检过期，重新质检后才可归档。
- 历史跟进补充保持原伙伴快照，不自动替换为商机如今的伙伴。历史手工补充能力保留，不批量修改历史记录。

## 接口契约

`GET /api/v1/fde/visit-opportunities` 原有分页和本人可录入范围不变，额外返回现有列 `sales_channel`、`partner_id`、`partner_name`。未参与商机、无效关联依旧不可返回。销售的商机列表已包含这些字段。请求与归档接口不变。
