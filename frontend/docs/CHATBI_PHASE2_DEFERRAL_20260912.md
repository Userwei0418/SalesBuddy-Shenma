# 首页推送与主动问数的分期决定

状态：2026-09-12 用户确认，取代此前“当前首页默认正序并开放问数”的安排。

最新澄清：**只有问数前端交互留二期；后端中台接入与原 API 兜底现在继续完成，并通过业务逻辑逐个验收。**此前本文关于后端验收等待二期的安排已被本次用户确认取代，保留为过程记录。当前目标及受控断路测试见 [后端业务接入目标](../../backend/docs/AGENT_BUSINESS_INTEGRATION_GOAL_20260912.md)。

## 决定与背景

一期首页按业务动态推送使用，恢复最新卡片在上、历史卡片在下的倒序。主动文字/语音问数交互属于二期，当前默认隐藏入口，不实施截图中的“点击麦克风后选择跟进或问数”等新交互。

用户提供的沟通截图补充了此前记录未覆盖的业务背景：协作方说明，韩启微希望最新推送置顶，以便及时看到新消息；主动问数形成连续对话后，再按旧上新下处理更合适。该转述解释了原倒序设计的背景。以用户本次明确指令作为实施依据，不把截图里所有设想自动视为已批准需求。

此前代码追溯只查到 9 月 10 日前端集成引入倒序，未检索到明确需求，不等于该设计没有业务依据。本次补充后，不再将一期动态推送描述为“错误的聊天排序”。此前“回复在屏幕外”的实际观察仍有效，但其问数交互改进现在作为二期储备。

## 当前默认行为

- 首页最新动态在上，首次加载定位顶部；后台刷新不反复抢走用户阅读位置。
- 隐藏主动文字/语音问数输入，入口关闭时不发起问数、问数语音转写或录音权限申请。
- 客户认领、记录客户拜访、创建任务三个业务入口保留。已有拜访和管理任务录音流程不受问数开关影响。
- 不删除问数实现、原 AI 路径、60 秒等待、防重复提交、身份变化回调隔离、结果定位或正序能力。不修改业务数据库与生产中台开关。

## 代码开关

配置文件：[miniprogram/config.js](../miniprogram/config.js)。这是构建配置，修改后需重新编译；当前不向产品用户提供排序或问数开关界面。

| 配置 | 当前值 | 含义 |
| --- | --- | --- |
| `HOME_CHATBI_ENABLED` | `false` | 隐藏并停用首页主动问数；显式设为 `true` 才开放 |
| `HOME_MESSAGE_ORDER` | `"desc"` | 最新在上；设为 `"asc"` 切换旧上新下及尾部定位 |

两项独立配置。二期连续问答可采用 `true` + `"asc"`；仅调整展示方向不会自动开放问数。未配置或顺序值无效时仍使用一期默认行为。

## 当前实际调用路径，避免与中台联调混淆

用户随后询问中台日志为什么没有刚才小程序的问答。本次明确：00:27–00:34 的 4 次问数、00:40 和 00:49 的 2 次界面验收，均为原业务后端直接调用 `senseaudio-s2-lite`。关联任务按各自时间窗口只读核对到每次 1 条成功运行、1 条对应助手消息、1 次原模型 HTTP 200 调用。它们不是“先调用中台失败，再由原 AI 接手”的运行。

当前业务生产路径尚未切到中台；之前的真实中台成功样例在独立 Worker/隔离数据联调中完成。中台已创建、某个 Agent 已发布、独立联调成功、当前业务已切换和完整兜底验收是不同状态。中台日志不能用来查找未经过中台的原模型请求。

用户进一步追问后纠正数量口径：目前是 **1 个 Agent 在独立环境接通、当前业务环境启用 0 个**，不能只报“已接入 1 个”而省略环境。没有切换的原因是业务接入部署与启用尚未完成，并仍有真实网络兜底、异常空回答和版本管理验收；不是历史中台连通性证据失效。刚才 UI 验收不能替代“接一个测试一个”所需的业务中台链路验收。

用户新截图右上角还显示资源访问权限错误。仅凭截图无法确定是日志列表、详情还是其他请求被拒绝，不能把这一权限错误等同于“没有发生模型调用”。此处只记录观察，不声称平台权限已修复。

同次中台失败转真实原模型的完整网络兜底仍未验收；此前合成 HTTP 演练不能替代。二期重新开放问数前，应分别复核路由、日志、权限与兜底，并明确告知本次实际使用哪条链路。
