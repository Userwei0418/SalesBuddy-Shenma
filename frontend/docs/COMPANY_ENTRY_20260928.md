## 使用行为

- 公司入口支持登录页 `company=<公司码>`，以及微信 `scene=c=<短公司码>`。只用于选择公司，不授予账号或业务权限。
- 登录页显示后端确认的公司名称、公司码，通常不需要手填；通过“切换公司”仍可编辑公司码。原有唯一账号允许不填公司码。
- 新建公司的公司码规则由平台控制。登录兼容已有公司的历史码：规范为小写，长度 1–128，拒绝控制字符。scene 独立限定 32 个 ASCII 字符（包含 `c=`），只接受单个安全短码；较长或不适合 scene 的历史码使用普通 company 参数。
- 已登录打开不同公司的入口时，保留当前会话并显示确认。确认切换后退出原账号、清理 API/选项缓存并重建页面栈，再以新公司重新登录。取消或明确选择“继续当前公司”可保留原业务身份。
- 未知、损坏、冲突入口保留错误提示，不静默退回空公司登录或进入当前公司业务。网络错误允许重试。
- 记住账号只保存 API 地址、后端确认的公司码和账号标签，不保存密码。唯一账号首次登录成功后，可将旧空公司标签升级为服务器确认的公司；其他明确公司的同名账号仍保留。
- API 地址隔离记忆和新会话。公司查询、密码登录、权限回读发生乱序、离页或身份变化时，不以旧回执恢复其他公司的会话。

## 接口与发布依赖

- `GET /api/v1/auth/company-entry?company_code=...`：公开的精确查询，无 Bearer。仅返回 `{company_code, company_name}`；不存在/不可用统一 404，频率限制 429，不公开公司名单。
- 登录及当前身份 actor 可包含 `company_code`、`company_name`；权限始终以其既有角色、授权和租户为准。已选择公司而登录 actor 返回另一明确公司时，拒绝建立小程序会话。
- 旧 actor 缺少公司字段时保持原登录可用性，不把链接里的公司码当作已认证事实保存。
- 应先部署提供公司查询与 actor 元数据的配套后端，再交付此小程序版本；旧后端没有公司查询时，专属公司入口会提示确认失败，而非绕过检查继续登录。无公司码的唯一账号原登录仍兼容。
- 微信小程序码的生成、上传、真机扫码和正式发布不属于 VM 回归通过的结论，需整体本地验收和微信通道验收。
