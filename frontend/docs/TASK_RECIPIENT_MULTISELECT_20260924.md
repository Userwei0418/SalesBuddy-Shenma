# 待办负责人搜索与多选（第 2 项）

用户确认：选中多人时，每个人各自一条待办，独立接受、拒绝、执行和完成。用户授权判断 AI 入口的一致性，采用普通创建和 AI 采纳相同规则；一条建议采纳次数始终计一次。

## 交互与数据

- 从现有后端有效人员目录读取所有分页，按姓名、账号、部门或岗位展示文字检索；不写死人员名单，不新增拼音搜索承诺。
- 不默认选人；通过稳定人员 ID 勾选，同名人员显示账号区分。搜索、清除搜索、关闭再打开均保留勾选，可移除已选人员。
- 一次最多 100 人。提交确认显示人数及人员，内容、截止时间、优先级、客户/商机关联对本批一致。每个人得到独立任务和通知。
- 单人仍走原接口；多人走后端整批事务。任一人员失效或权限不足，整批回滚，没有成功一部分的隐含结果。
- AI 多选通过一次建议决定提交；每条任务保留来源建议。采纳后按姓名和账号区分并逐人打开任务详情；旧记录、旧客户端的首条 task/task_id 保持兼容。
- 日常待办不附带残留客户/商机；客户待办仍要求有效商机关联。选为负责人不授予额外 CRM 权限。

## 提交保护

确认弹窗和发送期间防重复点击；请求按用户、公司、API 地址和相同请求内容保留幂等标识。结果不确定时保留原提交，暂锁表单并提示重试，重试发送同一批内容；确定拒绝后允许修改。切换账号或退出页面后，迟到响应不写回执或跳转。已知保存成功后的本地回执缓存失败不会触发重新创建。

这些保护不是离线任务草稿功能；手工另建的新任务是新的提交意图。
