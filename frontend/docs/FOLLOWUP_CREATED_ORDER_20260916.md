# 跟进记录按最新录入排序

客户经营详情和商机详情的「全部跟进」统一请求 `GET /api/v1/visits?sort=created_desc`。新补录的历史拜访按实际录入时间显示在前面，拜访日期仍独立展示。

## 接口与分页约定

- 服务端按 `created_at DESC, id DESC` 排序。`created_at` 是实际入库时间；人工日期 `recorded_on`、`created_date` 与拜访日期 `interaction_at` 均不用于该排序。
- 每页 20 条，后续请求保留 `sort=created_desc` 和客户/商机范围，并优先传回服务端 `next_cursor`。游标应绑定排序和对象范围。
- 响应必须包含 `sort: "created_desc"`。旧服务静默忽略新查询参数时，前端提示局部重试，不把旧顺序标成最新录入顺序。
- 归一化时保留服务端列表顺序，不再按拜访日期重排分页结果；同时间记录及跨页顺序也由后端决定。
- 未显式指定排序的旧调用方及独立旧客户详情页维持旧契约。FDE「我的拜访记录」使用独立 `/fde/activity` 读模型，本改动不改变它的本人归档范围或统计规则。

## 展示

客户卡片增加实际录入时间和两行正文摘要，同时保留拜访日期、方式、跟进人及状态。商机全部跟进卡片增加实际录入时间。时间统一显示为北京时间，缺失真实创建时间时显示「未记录」，不以人工日期冒充。
