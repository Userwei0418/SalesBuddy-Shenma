# 跟进记录质检标签

## 展示口径

客户跟进列表、商机跟进列表和单条拜访详情共同使用 `visitSignal`。
标签展示已保存的记录质量审核结果，例如“质检合格 · 75 分”。
旧 `expectation_code` 表示业务目标达成情况，不参与质检标签计算。

- 使用已保存的 `quality_review.grade`，不以当前评分门槛重新计算历史等级。
- 优秀、良好、合格使用绿色；待完善使用黄色。
- 没有合法的 0–100 整数分数：灰色“暂无质检结果”。
- 有真实分数但没有已知等级：灰色“质检评分 · N 分”，不推断合格。
- 顶层与审核快照中有效分数矛盾：灰色“质检结果待核对”。
- `quality_review.next_action_passed` 仅用于解释下一步计划审核情况。

## 接口依赖

`GET /visits` 的客户/商机范围及分页结果需返回持久化评分摘要，与
`GET /visits/{id}` 保持一致：

```json
{
  "follow_up_score": 75,
  "quality_review": {
    "follow_up_score": 75,
    "grade": "合格",
    "next_action_passed": true
  }
}
```

缺失数据保留 null 或空摘要；不能补造分数、等级或目标达成状态。
原有客户/商机权限、`sort=created_desc`、游标和分页总量不变。
前端不逐条请求详情补评分，不触发重新 AI 评估。
