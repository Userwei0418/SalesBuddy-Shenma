## 运行方式

微信小程序通过 HTTPS API 访问服务器 API / Worker，由 PostgreSQL 保存和查询业务数据。连接已部署服务时，开发电脑无需启动后端或数据库；本地配套开发与测试应按 [本地环境说明](../docs/LOCAL_DEVELOPMENT.md) 启动独立前后端和数据库，并导入其生成的本地工程。源码默认接口为 `https://www.ericepc.com/api/v1`，配置在 `miniprogram/config.js`。两台电脑使用同一服务器与账号时，会操作同一份业务数据。

1. 在微信开发者工具中导入本 README 与 `project.config.json` 所在的目录。
2. 保留当前 AppID、`miniprogramRoot: miniprogram/` 及本机私有工程设置。项目是原生小程序，不需要 npm 构建，也不依赖云开发。
3. 如提示 AppID 无权限，请小程序管理员添加开发者权限。微信开发者权限与系统业务账号是两套权限。
4. 输入由运营开通的账号和密码，系统按账号授权自动识别身份；是否需要首次改密以服务器响应为准，产品不提供通用默认密码。
5. 可直接连接默认服务器，运行版本见当前状态。账号由运营另行提供；只有经单独授权的私有包才可能附带 `交付说明/账号登录说明.md`。

账号因多次尝试而受限时，运营可在 Web“账号与组织”中查看预计解除时间，并填写原因解除指定账号限制；网络登录保护仍保留。运营及管理员账号需由系统管理员维护。演示公司与正式公司的账号和数据分别管理，不在本 README 提供密码，也不形成产品默认密码。

## 数据与权限

- 所有经营数据由后端查询数据库；接口失败显示错误与重试，空数据保持空状态。`tests/` 中的虚构输入只供隔离测试使用，不属于小程序运行代码。
- 本轮线上合成业务验收限演示公司或批准的一次性验收租户；不向真实公司写合成客户、商机、跟进或业绩。真实公司飞书联调仅使用已批准的少量零指标投影/通知。部门、可见客户及商机范围由服务端权限决定；连接同一租户的写入是真实写入。
- 客户由运营建档；销售申请认领后等待运营审批。录入其他公司客户的拜访不自动认领，也不获得他人商机详情权限。
- 伙伴从运营维护的目录选择，商机绑定伙伴 ID；历史未知渠道需人工确认。30% 及以上阶段需至少一个完整季度计划，0 与未填写不同。
- 模型调用、语音识别和文件解析由服务器执行；业务 AI 产出供人确认，模型不能自行认领客户、创建商机或确认实绩。
- 首页保持最新动态在上，主动问数入口默认隐藏。公司发布的有效业务规则优先于页面默认值。

在仓库根目录执行 `node --test frontend/tests/*.test.js` 和 `python3 frontend/scripts/verify_frontend.py`。测试通过仍需微信开发者工具与真实设备的主链、视觉和网络验证。

仓库中的 `VERSION.json` 标明源码来源，`artifact_kind: source_tree` 不代表正在运行的后端。发行包通过 `scripts/package_frontend.py` 从已提交的最终 Git HEAD 生成版本信息，包含前端提交、经核验的服务器提交、数据库迁移版本与独立校验清单；后端源码或迁移尚未部署时拒绝打包。

最终合并和验收后，在仓库根目录运行：

```sh
python3 frontend/scripts/package_frontend.py --output-dir ../前端交付 --backend-revision <已核验的40位服务器提交> --database-version <已核验的Vxxx版本>
```

交付目录包含可直接导入的 `frontend/` 和相关 `docs/`；`--include-doc docs/文件名.md` 可追加已提交的接口、演示和交接材料。脚本不连接服务器，也不发布压缩包，需要交付负责人先核对 API、Worker 与数据库实际运行版本。交付包及 ZIP 各有 SHA-256 校验清单，不覆盖已有交付。

模型密钥、数据库密码、账号密码、会话缓存、`project.private.config.json` 和备份不得进入 Git。默认交付包不含凭证；只有用户明确授权提供演示账号时，才使用 `--private-accounts-file` 传入仓库外的专用账号说明绝对路径，写入本地交付包的 `交付说明/账号登录说明.md`，不打印内容，不上传公开仓库或公开 Release。演示故事可以虚构，但用于展示的记录必须经真实接口入库，并标明演示用途。

FDE 成员和负责人沿用五个主入口。前端读取 `/auth/me` 的操作能力，客户建档、认领、商业编辑、实绩变更及客户级 AI 建议关闭；商机与拜访专业建议可以由本人确认后转为任务；本人拜访录入默认开放，必须关联本人当前参与的商机，共用文字、语音、文件和AI整理流程。任务正常使用，问数属于二期，不展示相关入口。

商机共用表单提供“协助 FDE”搜索多选，详情按对象权限单独管理商机协助名单。FDE 负责人仅可增删本部门成员，其他部门已有成员显示只读；名单更新使用版本号和幂等重试保护。销售拜访的“本次协助 FDE”不默认勾选，使用顶层 `fde_participant_ids` 归档；普通协同人与实际 FDE 参与去重，未选旧成员不移出商机协助名单。

FDE 商机只统计有效参与项目，客户全景可读其他商机。协作看板使用 `/fde/dashboard`、`/fde/activity` 的真实记录，展示项目规模、本人归档、任务和账本事实。“我的”用 `/fde/profile` 的本人客观六维画像及真实 AI 建议；缺样本标未评估，不套销售绩效分数。团队汇总直接采用服务端去重结果，参与摘要无完整访问权时不能打开旧详情。协作加入、移出和拜访归档是消息回执；任务主动取消、拒绝与待交接分别展示。

## 2026-09-21 录音保存失败恢复

针对录音结束后本地保存失败：保存前即保留临时文件路径、文件名和临时标志；本地空间不足、文件失效、权限错误分别提示，并保留错误码。可重试保存原文件，或显式直接上传仍有效的临时文件。临时文件不等于持久草稿，微信清理或失效后仍可能无法恢复，不应清缓存来排除此问题。

网络上传失败保留本地文件；重新打开页面不会把临时文件当作已保存文件自动上传。待处理文件未完成前，新录音、新文件选择和结构化提交会提示先重试或移除，避免覆盖；主动返回选择保存时，必须先成功持久保存临时录音。草稿存储失败、接口同步异常、空保存回执也保留恢复入口。

验证：`node --test frontend/tests/visit-entry-draft.test.js`。覆盖真实错误回调形态与重试链路，不代替手机端录音验收。此为小程序源码修复，需要上传新的体验版后才能用于手机验收；不会通过后台部署自动进入既有1.0.6体验包。
