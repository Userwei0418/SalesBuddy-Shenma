# 商汤销售小浣熊 Agent 中台 · 安装说明

你把这个安装包发给同事。同事在自己的服务器执行下面的命令，就能搭建一套独立的中台。

这是**联网安装包、全新实例**。包含定制界面、深浅色 Logo、Agents BETA、知识库检索出处、Skills、模型主备切换、模型多 Key 和 CLI 扩展程序。保留原平台已关闭业务回答强制校验的行为。

安装后由同事创建自己的管理员，填写自己的模型 API Key，再创建或导入智能体。**不包含原平台的账号、智能体配置、聊天记录、知识库文件或 API Key**；也不会同步或影响原平台。已有智能体如需复用，应单独导出不含密钥的配置再导入。

## 1. 准备一台服务器

- 支持：Ubuntu 22.04 / 24.04，64 位 Intel/AMD（x86_64 / amd64）。此包不支持 ARM 或 Windows 直接运行。
- 建议：4 核 CPU、8GB 内存起步，16GB 更充裕；至少 25GB 可用磁盘，后续按知识库大小增加。
- 能访问 Docker Hub、Docker 软件源。模型和插件使用时还需要访问各自服务。
- 有 SSH 登录账号和 sudo 权限。
- 在云服务器安全组放行你选择的 TCP 端口，例如 **8443**。安装脚本不会自动改防火墙。

本包会下载若干 GB 基础镜像，耗时取决于网络。所有基础镜像均固定摘要，不会因 latest 更新而自动换版本。

## 2. 上传、解压

把 `Raccoon-Agent-Installer-20260923.tar.gz` 上传到同事服务器的家目录。可以使用服务器控制台的文件上传，或在自己电脑终端执行（替换账号和服务器 IP）：

```bash
scp Raccoon-Agent-Installer-20260923.tar.gz 用户名@服务器IP:~/
```

登录同事服务器后执行：

```bash
tar -xzf Raccoon-Agent-Installer-20260923.tar.gz
cd Raccoon-Agent-Installer-20260923
```

**后面的命令都在同事的 Linux 服务器执行，不是在你的 Mac 上执行。**

## 3. 安装运行环境

```bash
sudo bash prepare-ubuntu.sh
```

这一步安装 Docker、Python 等基础工具。已安装 Docker Compose 时会保留已有 Docker。遇到旧 Docker 包冲突时脚本会停止，请服务器管理员按 [Docker 官方说明](https://docs.docker.com/engine/install/ubuntu/)处理。

## 4. 安装中台

把示例里的 `你的服务器IP` 换成同事的真实 IP：

```bash
sudo bash install.sh --public-url https://你的服务器IP:8443
```

默认安装目录是 `/opt/raccoon-agent`。脚本生成独立密码、内部密钥和 HTTPS 证书，下载基础镜像，构建定制程序并启动服务。看到“通过就绪检查”后继续下一步。

如果下载中途失败，修好网络后用相同命令加 `--resume`：

```bash
sudo bash install.sh --public-url https://你的服务器IP:8443 --resume
```

不要换 URL，也不要删除数据目录重装。恢复安装会保留已经生成的密钥和数据。此脚本用于安装这个版本，不是后续升级脚本。

## 5. 打开页面、创建管理员

在服务器执行：

```bash
sudo cat /opt/raccoon-agent/首次登录.txt
```

里面有访问地址和**初始化口令**。浏览器打开地址，输入初始化口令，然后按页面创建自己的管理员账号和密码。

默认是自签名 HTTPS 证书，有效期一年，浏览器会提示证书不受信任。首次使用先与管理员核对服务器地址和证书，再信任证书。长期正式使用建议用自己的域名和受信任证书；安装时可直接传入：

```bash
sudo bash install.sh --public-url https://agent.example.com \
  --cert /完整路径/fullchain.pem --key /完整路径/privkey.pem
```

域名必须已解析到服务器。证书续期后替换安装目录 `runtime/tls/server.crt` / `server.key`，再由管理员重新加载 nginx。初始化口令、服务器私钥和安装后的 `.env` 不要发给其他人。

## 6. 配置模型、开始使用

1. 点击页面左下角头像，进入设置 → 模型供应商。
2. 安装需要的模型供应商插件，填写**你自己的** API Key、API 地址和模型名。
3. 配置工作空间的默认模型；知识库需要额外配置 Embedding，Rerank 按需要配置。
4. 进入 Agents，创建智能体、选主模型和备用模型、写提示词、挂知识库或工具，测试后发布。

模型服务不是安装包附赠的服务，额度和费用由对应模型账号承担。原实例安装的供应商插件和供应商专用适配配置不随业务存储复制；需在新实例重新安装与配置。SenseAudio 语音适配服务程序已包含，但语音模型的 Key 和模型条目仍需自行设置。

## 7. 开通创建多个工作空间（可选）

首次管理员创建成功后，在服务器执行，邮箱替换为新管理员邮箱：

```bash
sudo bash /opt/raccoon-agent/manage.sh enable-workspaces admin@example.com
```

刷新页面后可看到“创建工作空间”。它只给指定的现有空间所有者开通权限，不会创建隐藏管理员。

## 8. 同事通过 Codex / CLI 管理 Agent（可选）

先在网页邀请同事加入目标工作空间，并赋予编辑权限。在服务器执行：

```bash
sudo bash /opt/raccoon-agent/manage.sh grant-cli colleague@example.com "工作空间名称"
```

此版本个人 CLI 在每个新实例中绑定一个指定工作空间，可添加多位成员。成员必须已有编辑权限；默认没有任何人被预先授权。

将安装包内 `cli/fdectl.py` 单独交给同事。在同事电脑上执行：

```bash
export FDE_SERVER=https://你的服务器IP:8443
python3 fdectl.py auth login
python3 fdectl.py auth whoami
python3 fdectl.py list
```

浏览器必须使用本人账号确认。自签名证书需要管理员通过可信渠道提供 **server.crt 公共证书**，并在客户端用 `SSL_CERT_FILE=/证书路径/server.crt` 指定信任；不要使用跳过证书检查的办法，不要给同事 server.key。

创建前先准备 JSON 配置文件，再执行 `create --file 配置.json --dry-run`；确认后 `create --file 配置.json`。`get AGENT_ID` 查看配置和 revision，`configure` 用最新 revision 修改，`publish AGENT_ID --revision REVISION` 才会发布。完整参数见 `python3 fdectl.py --help`。

## 9. 常用维护命令

```bash
# 查看运行状态
sudo bash /opt/raccoon-agent/manage.sh status
# 检查页面、API 和各服务是否就绪
sudo bash /opt/raccoon-agent/manage.sh check
# 查看 API 最近日志
sudo bash /opt/raccoon-agent/manage.sh logs api
# 暂停 / 重新启动（保留数据）
sudo bash /opt/raccoon-agent/manage.sh stop
sudo bash /opt/raccoon-agent/manage.sh start
```

不要删除 `/opt/raccoon-agent/runtime/volumes` 或 Docker 数据卷，它们保存新实例的数据。备份应同时覆盖安装目录（包括 `.env` 与密钥）以及该实例的两个 Agent sandbox Docker 命名卷；可由服务器管理员在停止这个实例后做一致性快照。不要把安装后的目录当作公开安装包转发。

## 常见问题

- **网页打不开**：检查 URL/端口、安全组和服务状态；默认示例是 8443，地址里不能漏端口。
- **镜像下载超时**：服务器需要能访问 Docker 镜像仓库，网络恢复后用 `--resume`。不要改成来源不明的镜像。
- **目录已存在**：脚本不会覆盖现有数据。首次失败用相同参数加 `--resume`；第二套实例另选目录与端口。
- **登录后不能回答**：先配置有效的模型 Key，再给 Agent 选模型并发布。
- **邀请邮件收不到**：邮件服务不随安装包提供，需要管理员按实际邮箱服务配置 SMTP。
- **能直接复制现有业务吗**：这个包提供相同定制程序与界面，但数据从空白开始。整套账号、知识库和历史数据复制属于另一种有权限边界的数据迁移流程。
